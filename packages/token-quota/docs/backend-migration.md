# Token quota backend migration

The package owns the quota ledger, admission policy, HTTP business operations and client wire rules. Its release version is the literal `Version` in `backend/BotAgent.Package.TokenQuota.csproj`, registered in `build/release-projects.json`. The only project dependency is the public Core SDK, with its transitive public contracts. A binary SDK build supplies BotAgent.Core.dll, BotAgent.Plugin.Contracts.dll and BotAgent.Quota.Contracts.dll through PluginSdkPath.

`QuotaPlugin` keeps the reserved identity `preset.feature.token-quota`. Initialization only obtains the host-issued `IPackageDataStore`; it performs no database operation. The approved distribution must grant table `tenant_quotas`, state prefixes `quota:revision:` and `quota:receipts:`, usage projection, audit append, and receipt contract `quota.management` version `1`. Resource declarations alone do not grant access.

The actual management contract is `ITenantQuotaManagement`. It exposes quota reads, limit updates, revision-aware save, and original-key lookup. Metering is excluded: the independent host recorder remains available when this package is disabled or absent. The save path preserves the original journal representation, original-key-before-CAS ordering, 4096 receipts per caller, limit bounds, revision rules, and atomic limit/journal/safe-receipt/audit commit.

`PluginManager.GetContribution<T>` supplies a typed contract from an explicit provider. Host bindings for a package consumer use `GetDependencyContribution<T>` with an exact direct dependency. These return generation-bound proxies. Every synchronous or asynchronous invocation holds the consumer/provider closure until completion, including cancellation and exceptions. Old proxies cannot follow replacement providers. Deferred enumerables, nested asynchronous results, returned callbacks and disposable resources need separate lifetime contracts and are rejected. Packages use the scoped IPluginDependencies context capability, also exercised by the real P07 coordination chain, and do not acquire the private Engine registry.

The loader-to-registry `IPluginContributionSource` bridge is an implementation adapter, not an application service locator. It is never placed in the package context. Only shared interfaces marked `IPluginContribution` are eligible; private collectible interface identities are rejected. New contribution sources require cold startup. Resource gates are installed closed before registry publication, so Ready never precedes resource binding.

## Transition still in progress

The default host now loads the approved external package with the same reserved ID. It no longer registers TokenQuotaPresetPlugin or creates a legacy quota store for either HTTP surface. Host HTTP requests use CreateControlEntryPoint<IQuotaOperations> to obtain a current leased control contribution on each independent request; package-held proxies remain bound to their captured generation. ITenantQuotaManagement remains available for typed ledger callers. Disabled policy retains management. An absent package returns unavailable, while generic operation-receipt lookup and independent metering remain available.

The unused Storage/Headless TenantQuotaStore and Engine TokenQuotaPresetPlugin implementation types have been retired. Their two production Compile links are removed and the architecture guard rejects their reintroduction. QuotaLedger and QuotaAdmission now compile only into the package. Synthetic persistence/recovery probes use tests/shared/QuotaFixture.cs and direct test-only references to the real package; original transaction, clock, usage and receipt assertions remain. These retired implementation classes were not public plugin SDK contracts. The SQL limit remains 145.

The public quota types belong to BotAgent.Quota.Contracts 1.0.0, with Core and Panel type forwards and an approved host owner/version/hash pin. Actual old package binaries retain their DTO, exception and receipt behavior. QuotaHttpContract owns the three ZBA route descriptions, typed request dispatch and six OpenAPI schemas. The host explicitly binds its authenticated callbacks into a frozen generic endpoint catalog. The existing database schema migration still needs package aggregation. TokenQuotaDialog lives in the package and uses the public UI bridge; D1 shell collection remains. See docs/architecture/quota-contracts.md, docs/architecture/http-contract-registration.md and docs/architecture/host-plugin-distribution.md.

The isolated runtime test builds the unmodified package project and source against Core, Plugin.Contracts and Quota.Contracts binaries, without package feeds or private host project references. A second isolated build overrides only the package version to 1.0.1-preview.1; the runtime reports the full informational version without the build metadata suffix. The test stages host-approved offline releases, exercises actual quota transactions, and checks that version adoption invalidates old proxies while preserving original receipts. This establishes the backend seam, not full D1.1/D1.2, P07, runtime UI delivery, production adoption, or cross-platform acceptance.

## Approved management while business is disabled

The release declares Control: true. PrepareControlAsync captures a separate management data view; the ordinary initializer builds the reply-policy view. Both remain closed until publication. Host entry points preserve management during business disable and disabled cold startup; existing ordinary GetContribution references still fail when disabled. Control transactions and async invocation leases drain before unload. Actual default-host S51 checks cover enabled/disabled/restarted/physically absent states. See docs/architecture/plugin-control-lifecycle.md.

## HTTP ownership and compatibility

QuotaOperations owns modern list/save/find validation, sorting, UTC projection, source checks, revision and receipt behavior, and atomic audit creation. QuotaLegacyOperations owns the legacy tenant parsing, JSON shape, validation and post-commit audit behavior. Host adapters retain authentication, request framing, source-directory and masking callbacks, and transport/error framing. All callbacks are synchronous and stay inside the leased operation; masked display names are resolved after durable saves, preserving the prior ordering. Legacy post-commit audit failure still leaves the successful limit write committed.

The six ZBA quota DTOs moved from Panel into the quota contract without namespace or member changes. Panel forwards their old identities. A client independently compiled against the actual prior Panel DLL exchanges current request/result objects through those forwards. Existing URLs, caller scope, limits, revisions, business journal, safe receipt and missing-package behavior remain unchanged.

frontend/quotas.ts owns quota TypeScript DTOs, response guards and QuotaApi. It takes an authenticated generic transport and imports no host implementation. The web shell reexports the old types and delegates its existing methods. The module compiles independently with TypeScript; the existing component/unit suite and real-host Chromium, Firefox and WebKit tests exercise the assembled application. This is source ownership and compatibility evidence, not independent runtime UI delivery or user visual acceptance.

## UI source ownership

frontend/TokenQuotaDialog.vue now owns the form, quota intent/recovery state machine and responsive presentation. The shell supplies only three quota client methods and contracts/ui presentation services, with a captured-scope journal and host-bound configuration switch. Package title/summary/ID are declared in frontend/presentation.ts. Host TokenQuotaDialog.vue is a thin composition adapter and contains no quota save/recovery logic.

The frontend has its own package.json, lockfile and isolated build. Only package source and the public UI type contract are copied into the build fixture; module-ownership.json records four package modules with Vue as the only external runtime dependency. CI registers the same independent build. The emitted module is also exercised with a replacement public shell through server rendering. Existing unit/component, actual-host three-browser and responsive visual tests exercise the assembled page. See frontend/README.md and contracts/ui/README.md.

This does not establish D2 runtime asset adoption, approved frontend/backend generation matching or user visual acceptance. Schema migration ownership, runtime generation-bound route adoption and the wider R2 goals remain open. The current 14-to-15 transfer and inverse touch both generic metering and quota limits; retiring legacy implementation classes does not change their atomic recovery boundary.
