# ADR-0004：统一记忆的内置核心与逐事实授权

- 状态：首版原则与 D1–D8、补充语义已确认；2026-11-06 完成独立工作树内的首版本地实现及所列验收检查。未提交、部署或发布；覆盖边界见[本地验收记录](<../unified-memory-validation.md>)。
- 决策日期：2026-11-05。
- 关联：[Issue #153](https://github.com/ZhaoJun233/bot-agent/issues/153)。
- 适用范围：单个 BotAgent 部署内的事实记忆、普通聊天与 Agent 的受控读取。
- 当前授权：在独立工作树实现并用合成数据验证；不改其他工作树，不读取生产数据，不做历史扫描/回填，不部署或发布。

## 1. 决策摘要

**统一可复用的事实，不合并原始聊天；保留隔离，以本人逐事实、逐版本、逐目标会话的授权实现受控复用。**

身份、范围、授权、撤销、遗忘和统一读取规则由内置核心负责。首版只保留一种内置实现；摘要、检索排序与存储适配在有真实替换需求时再扩展，不提前建设通用记忆插件框架。

本文记录已经达成的产品与架构边界，不冻结尚未设计的接口、表结构、算法或界面。

## 2. 背景与问题

此前只读源码调研区分出以下能力，不能把它们统称为已经互通的“记忆”：

| 现有能力 | 调研观察与限制 |
| --- | --- |
| 会话历史 | 为当前会话构建近期上下文；已有同账号多实例的历史复用，不代表实例策略或工具权限也共享 |
| 成员画像与摘要 | 按当前群聊/私聊范围读取；面板跨范围展示不等于模型可以跨范围注入；关闭画像功能不等于停止采集或删除已有数据 |
| Agent 执行历史 | 有独立会话与“是否携带上文”的控制，不能与聊天事实记忆混为一谈 |
| 片段存储 | 已检查范围内可见存储/查询能力，但没有足够证据确认主聊天链路已接入完整片段召回 |
| 画像预设插件 | 主要承担功能门控，实际画像逻辑仍在宿主；现有进程内外部插件是受信任代码，不是沙箱 |

因此问题不是“是否撤掉所有隔离”，而是“哪些信息允许复用、由谁授权、授权在哪里强制执行”。调研未读取生产会话、人物档案、数据库、原始协议消息或聊天日志，也未运行功能验收；以上不构成线上效果证明。

## 3. 领域术语

以下为本决策的规范用语，不代表同名类型已经实现。

| 术语 | 定义 |
| --- | --- |
| 事实主体（Subject） | 事实所描述、且须对共享作出确认的本人；首版事实只能来自本人的明确表达 |
| 账号/来源范围（Account/source scope） | 身份与权限所在的平台、机器人账号和来源/实例上下文；不是可因历史复用而抹掉的边界 |
| 来源范围（Source scope） | 事实最初获准记录和使用的会话范围；撤销某个目标的共享不等于删除来源事实 |
| 目标会话（Target conversation） | 本人准确指定的共享目的地；不由群名、通配符、同名群或未来新群推导 |
| 候选事实（Candidate fact） | 从本人明确请求中提炼、等待本人确认的内容，不具备自动共享权限 |
| 事实版本（Fact version） | 一次确定的事实内容；内容修改产生新版本，旧授权不能扩展到新内容 |
| 共享授权（Sharing grant） | 经可验证身份的本人确认，允许一个事实版本在指定目标会话使用的授权 |
| 受控读取（Controlled retrieval） | 普通聊天、Agent 和受控扩展入口共同遵守的身份、范围、版本和有效授权检查 |
| 停用 / 撤销共享 / 遗忘 | 分别改变功能运行、目标使用权、事实及派生数据的保留状态；三者不能互作别名 |
| 最小化抑制标记（Suppression marker） | 仅用于防止已遗忘事实被旧材料自动重新提取的最少信息，不是可检索的事实副本 |

## 4. 已确认的决策及理由

### D1：核心内置，策略按需扩展

核心统一处理身份与来源范围、事实版本、授权、停用、撤销、遗忘、最小化审计及各入口的受控读取。摘要/提炼、关键词或向量检索、排序、存储适配属于可替换策略，但首版不承诺具体扩展 API。

**理由：**安全边界需要集中、可复核且行为一致，不能由每个策略插件各自解释；首版没有多个已验证的实现需求，先搭通用框架会增加接口和生命周期负担。

**信任边界：**受控接口不等于插件沙箱。不能承诺阻止任意受信任 DLL 直接访问进程可访问的数据；需要隔离不受信任代码时，应另立安全设计。

### D2：共享事实，不共享整个上下文

仅支持单部署内部复用，保留平台、账号、来源/实例策略和会话权限边界。不合并原始聊天记录，不改动现有会话 key、路由或同账号历史复用语义。Agent 执行历史及“携带上文”开关仍然独立。

**理由：**历史同源或身份相同，不等于对另一群体披露的授权；事实复用与执行权限也是两件事。

### D3：本人确认准确内容和准确目的地

只接受本人明确表达的低敏感事实；不接受模型推断的性格、第三方评价、人际关系或敏感信息。身份依据同平台可靠标识及账号/来源上下文验证，不能以昵称、头像或模型猜测建立关联。首版不做跨平台认人。

默认隔离，包括私聊到群聊。授权绑定“本人身份 + 事实版本 + 指定目标会话”；模型只能提出候选，不能自行授权或挑选共享目标。

向群共享前必须告知：事实可能用于群内可见回复，当前成员和后来加入的成员均可能看到；授权对象是确定会话，而非当时的成员快照。

**理由：**披露范围应由被描述的本人控制，不能把自动提炼、身份关联或加入新群当成同意。

### D4：显式请求起步，不追溯迁移

首版流程为：

> 本人明确要求记住/共享 → 提炼候选事实 → 在可验证本人身份的私聊中确认内容与目标会话 → 在授权范围内按需使用。

不批量扫描旧聊天，不把旧画像自动迁移为共享记忆。旧画像保留自己的范围限制和开关语义，不能成为新跨范围读取的旁路。

本人确认、查看、撤销和遗忘等管理操作在可验证身份的私聊中进行。管理员/面板可以停用或撤销，但不能代替本人扩大披露。群内操作及错误信息不能泄露候选清单、其他会话范围或身份关联列表。

**理由：**历史存在不等于授权存在；私聊管理避免在确认之前就泄露内容或关联关系。

### D5：多入口共用授权，无授权不回退

普通聊天只注入少量相关、有效授权的事实；Agent 按任务需要读取，执行相同检查。受控扩展入口也不能绕过核心规则。

工具执行权、发送权和记忆读取权彼此独立。身份或授权不确定时拒绝相应读取/共享，不退回更宽范围；检索失败时可以继续无额外记忆的聊天。

**理由：**宁可暂时没有召回，也不能为连贯性、召回率或管理员便利而越权。

### D6：内容变化不继承授权

内容修改产生新版本，新内容的共享须重新确认；本人否定的事实停止使用；未解决的冲突不注入，不由模型悄悄选取一种说法当作事实。

**理由：**对一个表述的同意不能自动扩大为对后来不同内容的同意，冲突也不能靠模型确信程度解决。

### D7：分别定义停用、撤销和遗忘

| 操作 | 停止什么 | 保留什么 / 不代表什么 |
| --- | --- | --- |
| 停用统一记忆 | 该功能的采集、提炼与模型用途读取/注入，覆盖聊天、Agent 和受控扩展 | 保留已有记忆；不等于删除事实，也不隐式改变旧画像功能 |
| 撤销共享 | 指定目标范围继续读取或使用该授权事实 | 来源范围可以保留；不等于撤回已经披露的消息 |
| 遗忘 | 删除指定事实及派生检索数据，阻止旧材料自动重新提取 | 只保留必要的最小化抑制标记；不等于删除原始聊天记录 |

抑制标记不能成为事实内容的副本或新的检索入口；具体形式及隐私边界须在实施设计中论证。

**理由：**开关、授权和数据删除属于不同维度，混用会给用户错误的隐私保证。

### D8：撤销覆盖待发送内容，但不承诺追溯收回

撤销必须覆盖缓存、新查询、并发读取和尚未发出的回复，发送前重新校验。由已撤销事实生成的待发送内容不能因为缓存已清理就放行；应阻止发送或重新生成，具体实现另定。

无法承诺收回已经发送的消息，或已经交给模型的内容。原始聊天保留/删除另有策略，不能随“遗忘记忆”被暗中改变。

**理由：**授权需要约束最终使用，而不只是查询入口；同时必须如实说明系统无法逆转的信息披露。

## 5. 替代方案与取舍

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| 永远只保留各会话孤立实现 | 不作为本次目标方案 | 隔离简单，但无法满足本人授权后的事实复用，也容易让聊天/Agent 各自维护规则 |
| 合并原始历史或建立全局人物档案 | 拒绝 | 暴露范围过大，不能用身份相同代替逐事实授权 |
| 模型自动提炼并自动跨群共享 | 拒绝 | 候选提炼不是本人同意，易把推测或敏感信息变成共享事实 |
| 全部记忆交给插件，各插件自行授权 | 拒绝 | 安全规则分散，行为与撤销语义难以统一，现有插件又不是沙箱 |
| 内置核心 + 一种内置策略实现 | 采用 | 集中安全不变量，先验证完整闭环，再按真实需求抽取替换点 |
| 现在就建通用插件/多后端框架 | 延后 | 尚无足够实际替换需求，不为假想扩展承担额外复杂度 |
| 管理员代理授权、跨平台自动认人、旧画像批量迁移 | 首版排除 | 分别缺乏主体同意、可靠身份依据或可继承的历史授权 |

## 6. 后果与代价

**收益：**共享范围可解释；聊天与 Agent 的授权行为一致；撤销与遗忘可验收；保留现有会话、来源策略和执行权限边界。

**成本：**需要私聊确认和版本管理，用户操作比自动画像多；首版没有历史回填，初期可召回事实较少；并发撤销与发送前检查增加实现复杂度；相关性筛选和保守拒绝可能降低召回率。

**限制：**无可靠身份或确认入口时不能通过管理员代签绕开；受信任插件不受沙箱保护；已经对外披露的内容不可追溯收回。

## 7. 验收标准（本地首版，按记录限定覆盖范围）

只使用合成数据和测试替身，不读取生产群聊、真实画像、生产数据库或原始协议事件。以下判定来自源码复核、独立探针及隔离真实宿主；不是所有平台竞态均已执行。命令、指纹、逐项证据和未动态覆盖项见[本地验收记录](<../unified-memory-validation.md>)。

- [x] AC1：本人明确请求后形成候选；本人确认准确内容与目标后，仅指定会话可使用被授权版本。
- [x] AC2：默认不串群、不把私聊事实泄露到群；同昵称/头像、不同账号或来源不能冒认或借权。
- [x] AC3：旧画像、历史和片段存储不能绕过共享授权；首版不自动迁移或批量回填。
- [x] AC4：向群共享时告知当前及后来成员的可见性；授权不扩展到同名群或未来新群。
- [x] AC5：管理员不能代理扩大授权；群内操作及错误信息不泄露候选、身份关联或其他会话范围。
- [x] AC6：聊天、Agent 与受控扩展入口执行一致检查；Agent 历史开关、工具权限和来源/路由策略保持独立。
- [x] AC7：内容修改不继承旧共享授权；本人否定停止使用；未解决冲突不注入。
- [x] AC8：停用阻止统一记忆的采集、提炼及聊天/Agent/受控扩展向模型提供事实，但不删除已有记忆；不把旧画像开关等同此语义。
- [x] AC9：撤销在缓存命中、并发读取、生成中及待发送场景仍有效；来源保留正确，待发送内容不会携带已撤销事实。
- [x] AC10：遗忘删除事实及派生检索数据，旧材料不会自动复活事实；抑制标记不成为内容副本，不宣称同时删除原始聊天。
- [x] AC11：身份/授权异常时关闭相应读取；检索异常时可无记忆回复，不回退到更宽权限。
- [x] AC12：公开测试与审计证据只含合成样例、形状、计数和判定，不含真实身份、对话、密钥或部署信息。

## 8. 已确认的补充语义与首版取舍

### 8.1 已确认的补充语义（2026-11-06）

维护者明确接受全部推荐并要求继续施工：

1. **遗忘与旧画像的交界：**遗忘后，同一事实不能继续经旧画像在本范围注入。如果无法可靠地精确过滤，停用该成员对应来源范围的旧画像注入，并明确告知影响；不删除原始聊天。
2. **修改后的旧版本寿命：**修改立即退役旧版本及其授权，新版本重新确认。本人否定和未解决冲突同样停止使用。
3. **来源范围如何成立：**最初提出“记住”请求的会话为来源。本人在经过验证的私聊中明确确认来源内使用及准确分享目标；私聊确认本身不改变来源归属，不暗中建立本地使用权。

### 8.2 首版实施选择（不改变 D1–D8）

1. **低敏判定采用封闭词汇，而非模型评分。** 仅接受语言、回复长度、解释方式三类固定偏好，不接受自由文本或历史扫描；通过确定语法的本人请求形成候选。
2. **单宿主内置授权核心。** 使用可靠原生身份、平台/机器人账号/驱动实例和精确会话；同账号不同实例的历史即使共享，也不能借用记忆授权。一个数据库只注册一个授权核心，不构建通用插件框架。
3. **事务化持久化。** 在既有数据库元数据事务中存储版本化快照，用修订 CAS 保持写入原子性；损坏、未知结构或写失败关闭相关读取，不扫描旧画像或聊天。逻辑删除不是 WAL、备份或介质擦除。
4. **凭据跟随本轮派生工作。** 模型请求开始及受控实际发送再次在授权锁下验证；不持锁等待网络。发送还须证明准确目标和有效来源，旧版本、撤销及遗忘不能只清缓存。已经开始的外部请求不在可收回保证内。
5. **保守限制副作用。** 消费了统一记忆或旧画像的回合只允许直接文本回答，禁用外部工具、自然 Agent 转交和后台动作，不把派生结果写入全局心情、研究缓存或 Agent 持久历史。空旧画像不限制普通无记忆回合。
6. **遗忘采用来源级抑制。** 标记仅保留本人及来源身份，首版停用该本人对应来源的旧画像注入，并阻止从该来源重新创建统一记忆事实候选，不承诺不可靠的逐句过滤；旧画像的同源消息存储和原始聊天保留不因此停止，旧画像模型用途读取受抑制。
7. **交互和验证范围。** 默认关闭，使用独立治理身份及私聊命令，不新增面板页面；本人确认、查看、撤销、否定和遗忘走统一核心。用独立探针和隔离真实宿主场景验证，不接触生产数据。
8. **旧画像来源证明先于读取。** 新实时消息使用包含完整来源、原生成员和精确会话/线程的版本化摘要键；当前请求的凭据不能给旧的、可能混合来源的 scalar 数据补办来源证明。旧档案保留但不回退注入，协议历史补录不为画像重新归属。无来源凭据的自动画像摘要暂时停用（不依赖统一记忆开关），直到实现相同的可撤销模型用途边界；不迁移旧内容。

准确命令、能力范围及恢复旧备份/人为破坏数据库等保证外情形见[首版操作与边界](<../unified-memory.md>)。这些技术选择在已获准的施工范围内；需要扩大披露或减弱撤销保证时仍须重新确认决策。

## 9. 非目标与后续动作

非目标：合并原始历史、全局人物档案、自动人格/关系推断、跨平台身份绑定、跨部署同步、批量历史回填、管理员扩大授权、提前搭建通用插件框架，以及将受信任 DLL 宣称为安全沙箱。

独立工作树内置核心、受控入口和本地验收已完成，证据按第 7 节映射。后续可继续补充验收记录明确列出的动态覆盖缺口；本次完成不代表批准生产迁移、提交、部署或发布。
