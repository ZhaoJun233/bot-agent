# Research contract ownership

BotAgent.Research.Contracts 1.0.0 owns IWebSearch, IResearchUseCase, IResearchDiagnostics, ILinkPreviewer, ResearchOptions, WebSearchHit and WebSearchResult. Namespaces, method signatures and the existing result description behavior remain unchanged. Core forwards all seven old type identities; Engine retains its existing search, research and link forwards. The contract depends only on BotAgent.Plugin.Contracts. It contains no network implementation, host settings, store or service locator.

The research distribution owns the shared declaration under preset.feature.websearch. The bundle binds the assembly name, version, SHA256 and owner into host-compiled authority and carries the exact DLL beside its business DLL. The loader reuses one Default-context contract identity; implementations remain in collectible contexts. Core's temporary forwarding edge keeps previously compiled packages compatible.

A provider can implement the host's research contract without depending on the research business plugin. Otherwise the consumer's provider dependency would form a cycle. The exception accepts only an exact match in the compiled host contract authority. An imported distribution or manifest cannot nominate a new host contract or change its owner, version or bytes. Ordinary third-party shared contracts still require their owner as a runtime dependency. The browser import parser checks reserved owner syntax; server preview and staging perform the authoritative match.

State containing such an independent host reference in Active, Previous or Pending requires at least reader 9. A forged lower header fails projection verification. Actual reader 8 must reject before hashing or interpreting execution, including an opaque future execution block with an intentionally stale digest. Numeric declarations require reader 10 and configuration bindings require reader 11. The current default research package includes configuration bindings and therefore requires reader 11. All shared contracts continue to require cold adoption.

ResearchContractChecks uses the saved real preceding Core and research ZIP, verifies that the old DLL had no direct reference to this assembly, and runs its search, page read, links and disabled diagnostics on the current host. ResearchPackageChecks separately compiles an actual research consumer and provider using only binary SDK inputs. Contract fixtures exercise independent builds, incompatible version/hash/owner, undeclared new references, prior generation/state preservation, and downgrade rejection. All responses and identifiers are synthetic.

ResearchHttpContract now owns the existing POST /api/search/test route, request interpretation, both response shapes and their schemas. The host adapter keeps authentication, origin checks, its existing JSON reader, response transport and control contribution resolution. URL priority, trimming, nullable fields, result descriptions, provider errors and the original malformed/type-shape behavior remain compatible; no new ZBA route is introduced. Independent SDK consumers exercise the same contract without a host or business implementation reference.

ResearchSettings owns the ten existing defaults and environment bindings, the nine editable legacy field definitions and numeric identities, and their original parsing, clamping and trimming rules. AppSettings and ConfigurationFieldId retain compatibility aliases. The panel translates the owned parser results into the existing FieldEdit values, and ConfigurationStore uses the owned numeric ranges and source normalization. Common storage limits and the existing revision/transaction/receipt writer stay in the configuration module. First-deployment env seeding uses only the scoped ResearchOptions; stored configurations retain the previous ignore-and-report behavior. HostResearchOptions still reads the current committed settings on every invocation.

The saved preceding runtime compiles one legacy consumer before migration. Its unchanged DLL runs against both runtime sets and compares 288 observations, including the old declarative field constructor, invalid JSON types, env fallback, stored settings, ranges, normalization and live option snapshots. Independent research contract builds reference only the supplied Plugin SDK; a separate binary-only consumer runs the public settings and HTTP contract checks without Core, Headless or a business DLL.

ResearchSettings also declares the existing five numeric ranges as optional Plugin SDK constraints. Their defaults, submitted values, approval fingerprints, schema hashes and frontend range hints now use the generic declarative rules. The nine legacy field parsers and environment behavior retain their previous compatibility semantics. See plugin-setting-numbers.md for integer, wire and state reader requirements.

The research bundle now collects its settings and configuration declaration from the owned IPluginConfigurationDefinition. Its ten bindings retain the original settings JSON as the single value carrier; nine existing fields are editable and webSearchReadMaxChars remains read-only. Package writes and legacy writes share one configuration version, transaction, audit and original-key receipt. Bound values are never copied into package overrides. The exact former empty package-settings state can be adopted and is preserved by the first bound commit; incompatible state is rejected.

The package obtains IPluginConfiguration through an explicitly approved business or control generation. Reads before Ready, business reads after disable, and either kind after removal or replacement fail. Approved control reads remain available while only the business module is disabled. Research interprets the immutable values using its owned rules on every operation, so the nine original immediate settings still apply immediately. Preparation does not read configuration. Installation, update and removal remain cold adoption; ordinary unbound package settings retain their former adoption behavior.

The generic declared-settings dialog renders the owned schema and shared values, including numeric hints, read-only permissions, invalid-draft focus, discard confirmation, original-key recovery and saved-but-unapplied errors. This is still the current host frontend build. Independently delivered UI assets, combination recovery, new-field storage outside the compatibility carrier, remaining model/tool extraction and complete P07/R2 acceptance remain open. See plugin-configuration-writer.md for the write boundary and state reader requirements.
