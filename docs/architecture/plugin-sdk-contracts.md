# Public plugin contract foundation

BotAgent.Plugin.Contracts is an independently versioned, dependency-free contract assembly. Version 1.0.0 owns IPluginContribution, IPluginControlContribution, AuditEvent, AuditVerification and IAuditChain. Their namespaces and signatures are unchanged. Core forwards all five old identities; Engine retains its existing audit forwards. PluginSettingDefinition also moves to this SDK with its exact existing record signature and a Core type forwarder, allowing independently built owners to reuse the generic declarative field shape. Declarations without numeric constraints retain their existing representation and validation semantics. See plugin-setting-numbers.md for the optional rules, public validation API and state reader requirements.

This boundary permits business contract assemblies to use contribution markers and audit values without depending back on Core. Core can forward their old public identities without creating a dependency cycle. Quota uses BotAgent.Quota.Contracts and research uses BotAgent.Research.Contracts. See quota-contracts.md and research-contracts.md for their ownership and compatibility boundaries.

The SDK also owns the generic public-page contract in BotAgent.Plugins.Net: IWebPageTransport, WebPageRequest and WebPageResponse. It exposes validation and a materialized GET result, with no raw client, response stream, arbitrary headers or model credentials. The optional read boundary preserves existing chunk-based behavior. The host supplies the implementation through the explicitly approved network.public-read permission and holds its generation lease through the complete read/disposal operation. This addition does not move research business contracts or approve package network access by itself. See plugin-resource-authorization.md for lifecycle and reader-version requirements.

Normal package builds reference Core and receive the contract assemblies transitively. Independent binary builds supply BotAgent.Core.dll and BotAgent.Plugin.Contracts.dll in PluginSdkPath; quota additionally supplies BotAgent.Quota.Contracts.dll, and research supplies BotAgent.Research.Contracts.dll. Both actual P07/P08 projects declare their required binary references. Each contract project has its own literal Version; project edges remove inherited host version properties.

The package loader returns the host's Default-context SDK assembly only for its exact assembly identity. An incompatible version or case-altered identity is refused before initialization; a bundled duplicate is never adopted. Shared business contracts also have their SDK reference name, version, culture and public key identity checked before any permanent Default load. Package SharedContracts declarations cannot claim either host SDK assembly. Private implementation dependencies remain collectible. This is a type-identity contract, not a managed-code sandbox.

The independent fixture builds against the actual preceding Core binary, whose five types were still defined in Core, and invokes the resulting plugin on the new host. It separately compiles an incompatible SDK version and proves pre-initialization rejection. Two shared business contract DLLs prove that the matching SDK reference keeps one marker identity and that the incompatible reference is rejected before permanent loading. Actual quota and research builds exercise current binary SDK references and retain their existing lifetime and transaction checks.

Architecture scanning includes the contract projects, rejects reverse references and checks the Docker build-time source closure. The source Dockerfile includes the SDK, both business contracts, default bundle producer and independent quota/research backends and templates. A static closure check does not establish that a Docker image has built or started.

This foundation does not complete business contract extraction, quota schema/routes/UI ownership, compatibility-source removal, or the full R2 acceptance matrix.

Managed chat tools opt in with `toolApiVersion: 1` in their approved package manifest. Omission or null preserves the earlier managed manifest representation and means no chat tool contribution. Other versions and the field on Python manifests are rejected; Python tools keep their existing protocol. The field participates in import normalization, approval fingerprints and lifecycle differences. A declaration anywhere in Active, Previous or Pending requires state reader 8. An older reader rejects the envelope before interpreting execution state. Ordinary packages retain their earlier minimum reader version.

Tool packages use cold adoption. During enabled preparation the loader resolves the actual `IToolContribution` once and checks it against the declaration before publishing the generation. A missing or undeclared contribution rejects the candidate and retains the previous state and executor. Disabled business instances are not initialized to discover tools; enabling through a cold rebuild performs the check. The prepared executor stays fixed until shutdown. The public tool types still reside in Core; this version declaration does not complete independent model or tool contract extraction. The independently versioned research contracts and their scoped configuration are described in research-contracts.md.

The Plugin SDK owns PluginConfigurationDeclaration, PluginConfigurationBinding, PluginConfigurationSnapshot, IPluginConfiguration and the build-only IPluginConfigurationDefinition. Explicit approved bindings describe non-secret fields, their old numeric identity, read-only state and trim policy. Every editable declaration must have one matching binding; duplicates, unsupported owners or versions, arbitrary field mappings and undeclared permissions are rejected. Configuration semantics participate in import normalization, schema/approval fingerprints and lifecycle previews. A declaration anywhere in Active, Previous or Pending requires reader 11. Reader 10 is tested as an actual saved runtime and rejects it before interpreting execution bytes.

The runtime reader returns only this owner's immutable values under its current business or control generation lease. It cannot return host settings, secrets or a service container. Candidate preparation receives the capability but cannot read until Ready. Business disable retires business reads while approved control reads remain available; removal or replacement retires both, and shutdown waits for entered reads to finish. This capability preserves the old research fields and their immediate application; it does not authorize new arbitrary fields, independent UI assets or online package replacement.
