# Host-approved default plugin distribution

The host build produces 9 independently versioned `system.*` core and platform plugin ZIPs (S01–S05 plus the 4 platform drivers and `mcp-tools`) from their package-owned `distribution.json` templates, compiled implementations, optional `web/` static UI assets, and owned contract DLLs. The 13 `preset.feature.*` conversation feature plugins (`digest`, `documents`, `knowledge`, `music`, `personal-todo`, `poke`, `profiles`, `scheduler`, `stickers`, `token-quota`, `vibes`, `voice`, `websearch`, `1.1.0+`) have been decoupled from the host bundle and are distributed on demand through the official marketplace repository (`ZhaoJun233/bot-agent-plugins`, `sourceKind = "official"`, `runtime = "dotnet"`), with zero pre-installed feature plugins and zero automatic startup downloads on fresh hosts. `BotAgent.PluginBundle` reads assembly metadata and collects package configuration definitions without initializing business modules, supplies owned contract versions/hashes, uses a fixed ZIP timestamp and sorted entries/index, prunes stale ZIP artifacts from the output directory, and generates the exact index bytes and SHA256 as host assembly metadata. External files cannot replace that authority. The ZIPs remain separate under `plugin-distribution` so system packages can be physically omitted.

Headless has build-only references to the producer and the 9 system packages, with both `ReferenceOutputAssembly=false` and `Private=false`. The first removes runtime assembly references; the second prevents transitive apphost and runtime-configuration content from being copied into the host output. Neither is a runtime dependency or a business assembly loaded into `Default`. The content list names only artifacts from the current index; stale ZIPs in the intermediate directory are not implicitly published. Both normal publish and `publish --no-build` include that content. Global host version, output and RID properties do not become the package's version or output location. An ordinary manifest cannot use the reserved `host-distribution://` locator or acquire resource/control grants by declaring them; instead, `OfficialPresetPolicy` pins `preset.feature.*` origins to the official marketplace release prefix while enforcing per-feature least-privilege resource profiles, shared contract identities, and read/upgrade compatibility for historical `1.0.0` `host-distribution://` envelopes already on disk.

At first startup, the host stages the 9 bundled `system.*` archives through the existing package store, then performs normal cold preparation and registry publication. Explicit enabled intent is retained. Any existing Active, Pending, Previous or uninstall state—including legacy `1.0.0` `host-distribution://` envelopes for migrated `preset.feature.*` plugins—is preserved without deleting user data or triggering automatic downloads. A host metadata adoption marker prevents re-creation after uninstall or physical removal; a crash after staging but before the marker is reconciled from existing Pending. Missing/corrupt archives or markers remain observable failures, without a legacy quota implementation fallback.

When a rebuilt host carries newly compiled built-in package digests, `HostPluginBundle.StageFirstUseAsync` performs a controlled host-authority upgrade before `ReconcileAsync`: an existing `installed.json` that fails strict approval solely because its release digest belongs to an older host build is verified structurally through `PluginStateEnvelope` (`formatVersion`, `minimumReaderVersion`, `executionSha256`, projection match) and confirmed to carry `host-distribution://<id>/<version>` across every non-null slot. Physically deleted directories (with `adopted == "1"`), tampered/corrupt/future-version/third-party metadata, and `.governance.json` revocations are never overwritten or bypassed; explicitly uninstalled built-in packages (`Active == null && Pending == null`, or `PendingUninstall == true`) have stale unapproved `Previous` slots cleared and remain uninstalled. Eligible active packages are staged as `Pending` under governance commit checks, activated normally while preserving user `desiredEnabled` and package configuration, and obsolete release archives are pruned only after activation succeeds. Source `distribution.json` templates intentionally keep `ui.assets[].sha256` blank or set to the all-zero placeholder; `BotAgent.PluginBundle` always computes authoritative asset digests and both the bundler and `PluginUiValidation` reject all-zero placeholder hashes in packaged artifacts.

Staging validates the complete ZIP in memory before publishing its pinned archive: hash and size, every expanded payload, safe paths and file/directory collisions, Python source rules, and exact shared-contract bytes and assembly identities. It does not materialize business DLLs merely to delete them. Activation still extracts into a fresh private directory and verifies the files again before contract binding and plugin initialization. Admission, governance commit, cancellation and pending-state publication keep their existing order.

Adoption identity includes the package store's physical directory and plugin ID. Windows resolution uses an OS metadata handle, including volume aliases not reported by LinkTarget; casing is normalized for the marker. Nonexistent suffixes resolve through their nearest existing ancestor. Unix retains symbolic-link resolution. This same physical-path resolver protects database process ownership and offline recovery. It does not identify distinct hard links, and explicit migration of an installation to a different physical data root still needs a state-transfer decision.

P08 keeps preset.feature.token-quota. The reply policy and both quota HTTP surfaces now call the actual loaded package. Per-request host control entry points choose the current prepared generation and then use normal invocation leases. Business disable leaves approved control management available. Cold uninstall or physical package absence removes management; the generic safe receipt endpoint and independent usage recorder continue without the quota package.

The source locator requires at least metadata reader 5 across Active/Previous/Pending. Numeric declarations require reader 10, configuration bindings require reader 11, and UI/adoption/exclusive-resource declarations (`ui`, `adoption`, `exclusiveResources`) require reader 12. Current readers reject a forged lower capability and real preceding readers reject new declarations without modifying bytes; complete deployment compatibility remains a separate gate. Multi-package exact dependency changes use the explicit `/zba/v1/plugins/bundle/preview` + `/zba/v1/plugins/bundle/apply` workflow rather than automatic unattended updates.

The public package contracts live in independently versioned `contracts/*` assemblies, with compiled host owner/version/hash pins and Core type forwards where compatibility is required. Sandboxed runtime UI delivery (`PluginUiFrame` + `PluginUiAssetService`) is implemented for packages declaring `ui` (`preset.feature.token-quota`, `preset.feature.stickers`, `preset.feature.scheduler`, `preset.feature.personal-todo`, and compatible community packages), while host-hosted S01–S04 infrastructure adapters and static `presentation.ts` registrations remain explicit transition surfaces. Local publish, synthetic host tests and physical ZIP removal do not prove production deployment, full Linux/Docker behavior, or user acceptance.

Installed-package presentation first uses an exact ID/version/hash catalog sidecar. When it is unavailable, a matching captured runtime name and description can describe an ordinary package without invoking plugin methods. The fallback is always unreviewed; only the store's complete approved distribution fingerprint grants official source status. Missing author, repository or license metadata is not invented, and an external package never becomes a built-in. This keeps disabled default packages identifiable while the catalog is offline.
