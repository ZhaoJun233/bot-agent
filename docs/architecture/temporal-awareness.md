# 时效感知与不确定性（普通对话）

> 面向 #97：普通聊天里「现在/最近/最新」这类时效问题，模型没有时钟、也不知道自己的知识截止到哪天。
> 这一页记录**我们到底给了模型什么**、边界在哪、由哪些测试守着。

## 1. 时间从哪来

- 唯一来源：`src/BotAgent.Model/Model/PromptBuilder.cs` 的 `BuildIdentitySection`，取 `Clock.Now`（`BotAgent.Model.Clock`）。
  测试用 `Clock.Use(new FrozenPromptClock())` 固定，所以提示词里的时间可断言。
- 注入内容：`yyyy-MM-dd HH:mm`、时段词（凌晨/早上/上午/中午/下午/傍晚/晚上/深夜）、星期、UTC 偏移；
  并明确写「这是本机配置时区，也是唯一的时间基准」。
- 相对时间（今天/昨天/明天/这周/刚刚/上次）全部以这个基准算；「现在几点/今天几号」直接按它答，不搜索。

## 2. 时间基准的权威性（跨时区 / 跨日）

- **宿主时钟是唯一基准**：执行环境时间就是它（同源），但用户文本里报的时间**不是**系统事实 ——
  提示词写明「他报的时间也只是他说的，基准仍是上面这条」，避免把群友的一句「现在都十一点了吧」当成现在。
- 跨时区：提示词里带 UTC 偏移，问「你那边现在几点」按偏移换算，不让模型自己编时区。
- 跨日：日期与时刻同源，避免「23:59 说成今天」这类边界错误（时段词由同一次 `Clock.Now` 算出）。

## 3. 知识截止：默认未知，绝不写死日期

- 现在**没有**可配置的知识截止日期（加它要动配置契约：字段号、视图、两条保存路径、迁移，成本与 #133 同类）。
- 因此提示词只说两件事：① 你知道自己有截止时间，但**不确定是哪天**；② 别自称「截至某年某月」。
  测试会断言提示词里不出现 `截至 20xx` 这类伪造截止。
- 不因为没印象就否认新事实：比截止更新的事（新番/新版本/新政策/人事变动），说「我这边可能还没更新」，
  不说「没有这回事 / 早有了 / 是假的」。
- 用户说的新消息只算**未确认说法**：可以顺着聊，但不替用户升级成「官方确认」。

## 4. 联网核实：三种结果要分清

`[联网搜索]` 段在开关打开时注入（关闭时整段不出现，但时间与时效边界仍在）：

| 结果 | 提示词要求 |
| --- | --- |
| 查到新资料 | 用来源与时间说清楚，下一轮据此答 |
| 查到旧资料 | 说清是旧的 —— **事件发生时间 ≠ 你检索的时间** |
| 没查到 / 读不到 | 如实说没查到，勿用旧信息假装新结果，不补编结论 |

稳定知识（数学/成语/语法、史地常识、代码、可计算或上下文已知）不搜索；同一件事不连着搜两次。

## 6. 已知边界

- 合成桩（`MockOpenAi`）只能断言「模型看到什么」，不能断言「模型怎么答」；「是否真的没否认新事实」只能在真实模型上观察。
- 不引入可配置截止日期：宁可如实说未知，也不写一个猜的日期（写了就等于给模型一个假权威）。
- 不为了时效问题给普通聊天加固定免责声明：提示词要求「拿不准才说拿不准」，闲聊不触发。
