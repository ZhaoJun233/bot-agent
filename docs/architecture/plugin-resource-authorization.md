# 包资源授权与运行代次

## 声明与宿主授权

托管包技术清单可以声明 `data`：`tables`、`statePrefixes`、`usage`、`audit` 和可选 `receipt { contract, version }`。表和状态前缀各最多 32 项；通用计量表、meta 与安全回执索引不接受包 SQL/状态前缀直访。`usage`、`audit` 和 `receipt` 分别授权既有受控端口，不开放裸连接。Python v2 不接受此声明。

声明本身不授予访问权。`PluginResourceAuthorizations` 由宿主可信组合代码建立，固定完整批准清单的摘要，包括 ZIP 摘要、入口、依赖、配置和资源声明；默认集合为空。可信发行索引提供自己的批准集合。普通非预设 ID 也使用同一能力路径，但须有宿主的显式批准，不能从 installed.json、导入请求或包代码自动生成授权。

一个宿主的完整批准集合必须一起检查资源所有权。不同 owner 不能使用同一表或相互覆盖的状态前缀；同 owner 的不同批准版本可以保留自己的资源。清单变更后旧授权不生效。安装暂存和实际启动都会校验，伪造磁盘声明不能绕过启动检查；拒绝时保留原磁盘证据。

## 生命周期

初始化上下文只暴露该包自己的 `IPackageDataStore`；没有声明时也不会继承外层的全局数据能力。准备阶段的读写均返回 `plugin_data_not_ready`。只有候选发布进入实际 PluginManager generation 后，数据能力才绑定对应 InvocationGate。

每次事务取得包及其传递依赖的代次租约，贯穿等待数据库写协调、执行回调和提交/回滚。等待数据库后、进入回调前再次检查就绪状态。停用、移除、失败依赖或提供方换代会拒绝后续调用，包括捕获并保留的数据接口引用；已进入回调的事务可以完成，卸载必须等待租约排空。

数据声明、公共网页资源和共享契约都只允许冷采用；市场更新报告需要重启。可信保留 ID 继续不能进入旧在线重载 API。`ApplyAtStartupAsync` 是可信启动协调入口，不构成任意在线调用的授权。迁移、建表与授权集合的组装仍由宿主受控冷启动路径负责。

## 公共网页读取

托管 API v1 包在既有 `permissions` 集合中声明 `network.public-read`，使用 SDK 的 `IWebPageTransport`。它仍需要完整清单的可信批准，声明、磁盘元数据或增加另一项权限都不能自行扩大批准范围。宿主必须明确注入对应传输实现；缺少实现时返回 `plugin_web_transport_missing`，没有声明时不会继承外层能力。Python v2 不接受这项声明。

`TryValidate` 和 `GetAsync` 都绑定实际运行代次。准备阶段、停用及退役后的调用返回 `plugin_web_not_ready`；整次 HTTP 请求、重定向、正文读取及释放都在租约内。`GetAsync` 返回最终 URI、状态码和已读取的字节，不向包暴露响应、流或客户端。异常和取消同样释放租约。获批的 Control 使用单独的句柄和控制生命周期，业务停用不影响它，完整移除仍等待它排空。

宿主实现复用 `SafeUrl` 和安全 `HttpFetcher`：逐跳检查目标、手工处理最多五次重定向，并由实际连接回调验证及固定 DNS 地址。请求只有 GET、User-Agent 与 Accept-Language，不接收任意请求头或模型凭据。构造传输时必须使用安全网页客户端；测试中的私网开关由宿主策略提供，包不能选择。非成功响应不读取正文。可选读取边界保留旧解析器行为：每次最多读 32 KiB，再检查累计长度，因此它是块边界停止条件，可能超过声明值，不能作为严格字节上限。省略边界时保留原搜索源的完整读取行为。

本步只建立公共网页能力与搜索/链接消费者的接口。模型请求、完整 AppSettings 依赖、实际 P07 默认发行装配和业务契约归属仍待迁移；宿主当前的内置搜索不能据此视为已采用独立包。

## 回执与格式

有 receipt 授权时，宿主固定 owner、契约和版本，generation 为完整批准清单摘要加本次激活随机 ID。同版本重启仍产生新激活身份。包调用只能提供调用范围、原键、请求摘要与终态，不能覆盖 owner 或 generation。旧键继续属于旧记录，不能借新代次重标。业务幂等实现仍应先重放自己的原始结果，再决定是否执行新事务。

Data 全部语义参与后台意图/生命周期指纹、前端技术导入和变更预览。资源集合排序不改变语义；新增、删除、布尔权限或回执契约变化都会改变批准内容。无 Data 的既有指纹不变。最低元数据 reader 按 Active、Previous、Pending 中全部语义计算：普通清单 1、共享契约 2、Data 3、Control 4、离线发行来源 5、公共网页权限 6。`permissions` 的既有归一化、预览和完整清单摘要涵盖新权限，无需新增前端字段。降低信封标记不能掩盖实际语义要求；候选宿主的 PE 元数据也必须声明兼容版本。

## 验证及未完成项

PluginMarketProbe 的真实 DLL 验证准备访问拒绝、声明/磁盘不能自授权、跨 owner 资源冲突、运行写入、代次回执、停用与提供方换代拒绝旧引用、同版本重启及事务排空。共享字段夹具同时检查后台和前端，不改旧指纹基线。

P08 已采用独立账本、配置贡献和默认 ZIP；历史 schema 14/15 的同源恢复输入仍由宿主保留，运行时 schema 准入未完成。P07 仍需完整业务搬迁和默认发行采用。进程内 DLL 具有宿主权限，本端口不等于恶意代码沙箱；组合恢复、Linux/Docker 与完整缺包验收仍由后续阶段完成。
