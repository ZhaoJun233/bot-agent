# 治理源刷新期限

JSON 导入预览会先刷新治理记录，再返回确认内容。此前刷新只沿用调用方取消；等待安装提交门闩、HTTP 响应头或未结束的正文时，控制接口可能一直不返回。

PluginGovernanceService.RefreshAsync(CancellationToken ct) 保持原签名，建立固定五秒的联动取消令牌。门闩等待、重定向与响应读取、缓存写入共同消耗这份预算。取得门闩后才处理和发布源状态，等待期限耗尽时保留已有状态。网络与流接收同一取消令牌并正常释放，不使用遗弃后台任务的超时包装。

调用方取消仍向调用方传播；内部期限耗尽沿用 unavailable/cached/unknown。撤回记录保留、时间戳单调合并、feed/cache 大小约束和安装提交拒绝规则保持原契约。新拒绝记录即使缓存持久化失败，也继续保护当前进程中的获取路径。安装提交仍持有同一个门闩，刷新不越过提交租约。

公共 API 探针覆盖慢响应头、慢正文、撤回缓存、提交门闩等待、调用方取消和排队后的剩余预算。合成宿主的端到端夹具使用保留域 example.invalid，避免在线公共治理元数据改变测试输入；市场治理探针另行覆盖 fresh、撤回和缓存行为。原安装、确认和回执断言不变。

这是控制接口等待行为的修复。动态配置真源、完整 P07、运行时 UI、依赖组合及 R2 总验收继续按执行计划推进。
