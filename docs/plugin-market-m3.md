# 插件市场 M3：生命周期与迁移候选

> 本地 M3 候选已完成；独立原生检查与默认浏览器矩阵通过，headed 矩阵结果见下表。这不是发布、部署或整条 issue #152 验收通过的声明。沿用 [M2 安全导入边界](./plugin-market-m2.md)，不改变新装默认停用。

## 操作边界

| 操作 | 候选与确认 | 不会做什么 |
| --- | --- | --- |
| 升级 | 市场、仓库选择或高级 JSON 经同一生命周期预览；只接受严格更高的 SemVer 优先级 | 不自动升级，不自动装依赖，不借升级绕开同版内容变更检查 |
| 普通回滚 | 服务端安装记录中的 Previous；确认后重新核验本地缓存 ZIP | 不信任客户端自报旧版，不从孤立目录恢复，不回滚用户数据 |
| 失败候选恢复 | 已知失败升级留下 Active + Pending 时，显式确认放弃失败 Pending 并恢复仍可用的 Active | 不把未知／进行中的操作当失败，不自动清理，不伪造 Previous |
| 卸载 | 展示当前包清单、依赖影响与保留范围后确认；首次安装失败的 Pending-only 包也须凭终态失败依据显式确认 | 宿主不主动删除插件配置、secret 引用或用户数据，不把卸载等同清空所有文件 |

内置功能没有伪造的软件包生命周期按钮。SemVer 比较仅用于新升级入口；相同优先级、降级及不明确版本不按升级受理。升级／回滚目标与已保存配置不兼容时阻断，不清空配置以“完成迁移”。第三方插件自己的初始化／卸载逻辑仍可能改变其数据；保留承诺不是进程沙箱或自动备份。

## 预览与确认

生命周期预览是 Admin 只读操作：不下载 ZIP、不装载程序集、不写配置、不占用操作回执。它展示当前／目标版本、来源与完整技术清单差异：入口、框架/API、最低宿主版本、下载地址、哈希、权限、精确版本依赖，以及配置定义。它不显示已保存的设置值或 secret 值。

预览绑定调用者、安装代际、源快照、设置 schema／修订和启用意图（卸载绑定不解释内容的持久化设置指纹），有效期 10 分钟，与 M2 共用 64 项／8 MiB 有界缓存。确认前再次验证；候选、源引用、状态或配置变化时重新预览并确认，不能沿用旧勾选。包完整性在真正确认阶段核验，不将预览中的“待核验”写成已通过。

升级／回滚保留启用意图，可能热应用，也可能要求重启；“待重启”不是已加载。卸载保留配置和启用意图记录；之后重新安装仍遵守 M2 新装默认停用。停用不保证零代码执行：进程内 .NET 包可能执行模块初始化、构造函数或属性读取；权限声明、来源说明与 SHA-256 都不是沙箱。

## 失败与恢复

1. 响应丢失或结果未知时，保留原操作键，只查原回执，不能自动用新键重试。
2. 回执必须匹配操作键、目标插件和操作种类。目标不符、仍未知或仍进行中时保持恢复提示。
3. 已确定失败且旧版仍可用时，恢复预览展示绑定快照中的失败 Pending 与 Active；即使首次升级没有 Previous，也可在证据充分时显式恢复 Active。
4. 首次安装失败且尚无 Active 时，可显式卸载未生效的 Pending 安装候选；不能把它展示成正在工作的版本，也不能冒充回滚。它同样要求可核对的终态失败依据。
5. 恢复依据限于同一调用者、同一包状态的终态失败回执；更新的未知操作覆盖旧失败依据。其他插件的变化不应单凭全局代际使新式包级依据失效。
6. 回执沿用 7 天／256 条上限。缺失、过期、损坏或无法核对的依据必须阻断并提示人工核对；不通过删除 Pending、重置设置或更换操作键“消除”未知结果。
7. 已完成的旧客户端回执仍可按原意图重放；新的升级／卸载请求必须携带生命周期 previewId。拒绝缺失／篡改预览时，不先预留回执或下载包。

接口与兼容迁移详见 [API 路由表](./api-surface.md)。
