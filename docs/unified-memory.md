# 统一记忆：首版操作与边界

设计依据：[ADR 0004](<decisions/0004-unified-memory-authorization.md>)。本功能不是合并聊天记录，也不是全局人物画像。只在一个 BotAgent 宿主中，由内置核心管理本人明确设置的偏好、版本和逐目标授权。

## 1. 默认关闭，治理权独立

首次启动默认关闭。治理身份仅由 `BOTAGENT_UNIFIED_MEMORY_ADMIN` 的 JSON 配置确定，不复用 Agent、工具或面板权限。示例仅含合成身份：

```json
{"PlatformId":"qq.private","AccountScope":"legacy","InstanceId":"","NativeUserId":"10001"}
```

四个值必须精确匹配实际来源身份；`InstanceId` 的空字符串只代表既有默认实例，绝不是任意实例。缺失或无效配置不会授予治理权。配置好的管理员在可验证的本人私聊中使用 `//memory start` / `//memory stop`；状态持久化。管理员不能替他人确认事实或扩大目标范围。首版没有新增面板管理页面，也不提供管理员浏览他人候选的入口。

`stop` 停止统一记忆的采集及模型用途读取，但保留管理数据；旧画像自己的开关独立。遗忘对旧画像的保护不因统一记忆停用而失效。

## 2. 只接受有限偏好，不接收自由文本事实

| 命令类别 | 允许值 | 含义 |
| --- | --- | --- |
| `language` | `zh`、`en`、`ja` | 回复语言 |
| `length` | `brief`、`detailed` | 回复长度 |
| `explanation` | `examples`、`step-by-step` | 解释方式 |

本版不做模型自动提炼、旧画像迁移或历史扫描。自由文本、敏感信息、第三方评价、性格和关系推断不在接受范围内。检索只针对本轮可靠识别的本人，不枚举群内其他人的统一记忆。

## 3. 请求、本人私聊确认、使用

1. 在希望作为来源的会话中明确请求，例如 `//memory remember length brief`。可追加 `to <scope> ...`，最多八个准确目标，必须属于同一平台、机器人账号和驱动实例。
2. 在与机器人的本人私聊中执行 `//memory list`，再用 `//memory show <事实ID>` 核对内容、版本、原始来源及全部目标。群内只返回通用提示，不列事实或确认令牌。
3. 复制 `show` 展示的确认命令，明确同意来源内使用。若涉及群，必须确认当前及以后加入的成员都可能看到回复。确认令牌绑定准确内容、版本、来源和目标；私聊确认不会把来源改成私聊。
4. 之后普通聊天和 Agent 任务只能在授权会话中按需读取少量相关偏好。确认与事实管理信息不会送入模型提示词。

`scope` 格式为 `scope:平台/机器人账号/驱动实例/private或group或channel/原生目标ID/线程`。字段 URI 转义，`~` 表示无线程，`!` 后接转义后的线程 ID。可在本人私聊使用 `//memory scope` 获取该私聊的准确范围；其他目标必须提供准确身份，不按群名、昵称或头像猜测。不要在群内粘贴事实 ID、确认令牌或私聊管理输出。

## 4. 修改、撤销、否定、遗忘

- `//memory edit <事实ID> <版本> <类别> <值> [to <scope> ...]`：立即退役旧版本及全部旧授权；新版本需重新私聊确认。
- `//memory revoke <事实ID> <scope>`：停止指定目标的未来使用，保留来源使用权。
- `//memory reject <事实ID>`：本人否定，停止该事实使用。
- `//memory forget <事实ID>`：逻辑删除事实及授权，保留不含事实内容的抑制标记。首版采取保守策略：阻止该本人在相同来源重新创建统一记忆事实候选，并禁止对应来源的旧画像注入；不做不可靠的逐句过滤。旧画像的同源消息存储和原始聊天保留不因此停止，停止的是其模型用途读取。操作提示会说明影响。

未解决的同类冲突不会注入。以上管理必须经过可靠的本人私聊身份验证，不能靠消息文本伪造身份。

## 5. 安全取舍与真实限制

- **旧画像不能借用当前请求的来源身份。** 接线后的宿主只消费带完整平台、账号、来源实例、原生成员及会话/线程命名空间的画像数据；命名空间是不可逆摘要键，不是授权凭据。可信实时消息写入这一范围，协议历史补录不为画像重新归属。旧 scalar 档案（包括旧手工档案）保留在存储/原管理路径，但来源不可证明时不再注入模型；不迁移、不回填，也不向旧 key 回退。
- **本版暂不运行旧画像自动摘要。** 旧后台队列不能证明来源和持有可撤销凭据，因此接线宿主即使开启旧摘要设置、或关闭统一记忆功能，也不会启动该模型任务；可信同源消息片段仍可用于旧画像上下文。此限制不删除原档案，不改变原始聊天保留策略。
- 每次读取产生内存中的使用凭据，后续模型请求和受控发送重新检查；撤销、编辑、否定、遗忘、停用或来源失效会阻止相应待处理内容继续使用。具体发送目标必须与授权来源上下文一致。
- **凡本轮消费了统一记忆或旧画像文本，只允许直接文本回答。** 不执行外部工具、自然 Agent 转交、研究缓存写入、语音/歌曲/表情等后台动作，也不将派生内容写入全局心情、氛围或 Agent 持久历史。空旧画像不触发此限制。Agent 历史开关本身保持原有语义。
- 诊断只记录类型、长度、计数等形状，不持久化未发送的记忆派生回复或模型自定义原因。
- 遗忘不删除原始聊天，不撤回已发送消息，也不能收回已经开始的外部请求或已经交给模型的内容。原始聊天和曾公开的回复仍遵循各自保留策略。
- SQLite 采用原有元数据事务中的版本化快照及修订 CAS，不新增独立数据库。损坏或不支持的结构关闭相关读取；不自动回退成空白有效授权。逻辑删除不等于擦除数据库 WAL、备份或介质。手工删除整个快照、恢复旧备份以及多宿主共享同一库不属于本版撤销保证。
- 受信任的进程内 DLL 不是沙箱。本版不提供跨进程、跨部署或恶意插件隔离保证。

## 6. 验证入口

四个独立合成探针覆盖核心/存储、命令、宿主调用封装及实际模型/发送边界；集成场景 `s153` 使用隔离临时数据目录与 MockOneBot/MockOpenAi 启动真实 Headless 子进程。测试不连接生产服务。

先构建 Headless，再执行需要它的集成场景；仅构建 harness 不会更新宿主二进制。测试结果、候选指纹与未覆盖边界见[本地验收记录](<unified-memory-validation.md>)。
