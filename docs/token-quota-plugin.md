# Token 配额插件

Token 配额以官方预设插件 `preset.feature.token-quota` 注册，默认启用；沿用插件配置中的启用状态，改变状态后重启宿主生效。能力页的「Token 配额」卡片提供设置入口。

## 行为边界

- 插件拥有每日额度的回复准入策略。达到上限时，普通回复与主动回复静默；直接提及机器人仍可回复，且计入用量。主动回复不能借用旧的提及绕过限制。
- 回复管线只调用通用 `IReplyPolicyPlugin` 扩展点，通过 `ITokenUsageRecorder` 记录已完成聊天模型调用的用量，不直接判断配额。
- 停用插件只停用额度拦截；继续记账。重新启用后按当天累计用量判断，调高上限不清除已有用量。
- 当前计量范围仍是聊天回复模型路径（有限步进循环汇总的 prompt/completion）。后台画像、独立 Agent 任务、媒体服务等调用不因此变为全局计费范围；本次保持原有口径。
- 日界为 UTC 00:00；每个原始 SourceKey 独立，包括不同平台的前缀。界面显示名称遵守脱敏设置，写入与关联始终使用原始 key。

## 数据兼容

继续使用原 `tenant_quotas` 表及已有字段。旧额度、当天 prompt/completion 用量、重置日期与节能状态直接沿用，不重建表、不清空数据、不改 SourceKey。新增的管理版本和操作回执保存在数据库元数据中，与额度变更一起提交；用量增加不会制造配置版本冲突。旧 `/api/quotas` 接口继续兼容，其额度变更也推进同一管理版本。

默认每日上限仍为 50,000 Token，可配置范围仍为 1–1,000,000,000。额度是下一轮准入门限，不是按 Token 预留的硬账单上限；进行中的调用与直接提及可能继续增加用量。

## 管理接口

- `GET /zba/v1/quotas`：读取已登记会话的额度、用量、重置时间和配置版本；不接受任意 key 创建会话。
- `POST /zba/v1/quotas/save`：管理员提交 `sourceKey`、`expectedRevision`、`idempotencyKey` 和 `dailyTokenLimit`。
- `POST /zba/v1/quotas/find`：按原操作键查询持久化回执。回执按认证主体隔离，重复请求返回原结果；同键不同内容拒绝写入。回执不会自动过期或被清理，每个认证主体最多保留 4,096 条保存回执；满额返回 `503 quota_receipt_capacity` 并拒绝新的保存，已有回执仍可查询和回放。该限制是当前管理接口的运维边界，不能通过清理回执恢复后重发旧操作键。

保存时版本不匹配保留草稿，读取最新版本后再确认。网络错误、服务端错误或成功响应无法解析时视为结果未知，锁定修改并仅核对原回执，不自动重发保存。查询暂未找到回执不能证明原请求不会完成。

接口使用现有 ZBA Bearer 鉴权及管理员写权限，Token 仍只存在浏览器内存。能力页 → Token 配额 →「配额拦截插件」可保存启用或停用设置，页面分别显示保存设置与运行状态。启停使用现有 `registered.plugins` 配置事务（CAS 与回执），不引入第二套开关。保存不会自动重启；未确认的启停提交会锁定关闭和额度编辑，仅允许核对原回执。

回复策略插件抛出异常或返回格式无效的原因码时，本轮静默并记录固定 `reply_policy_error`，不转发异常文本。原因码只允许 1–64 位小写 ASCII 字母、数字和下划线。

## 验证

只使用合成会话与隔离临时数据库。策略探针覆盖超额静默、直接提及、主动回复、平台隔离与停用期间记账；存储/面板探针覆盖原数据复用、UTC 跨日、CAS 冲突、幂等回放、权限及重启持久化；前端测试覆盖只读、保存、冲突和结果未知核对。具体执行结果随本次交付记录，不将测试说明视为执行证据。
