## 6. 失败处理与上线 / 回滚边界

| 情况 | 处理 | 允许继续的范围 |
| --- | --- | --- |
| 契约、身份来源或旧表归属不明确 | 保留反例和问题，冻结相关写入；不猜值补齐 | 不依赖该契约的文档 / 错误处理切片 |
| 本地测试反例失败 | 先定位产品 / fixture / 测试环境原因；原始失败记录保留；修复后重跑原用例 | 未受影响的只读调查；不以扩大 allowlist 消除失败 |
| 官方接口未授权 / 内邀未获批 | 该能力标记 Deferred，隐藏执行入口并展示原因 | 其它已获准能力的验收，不宣布全部对齐完成 |
| 请求是否执行不明 | 记录 Unknown，停止自动重放，提供操作状态 | 只读状态核查；任何新的副作用操作另行裁决 |
| 新版本身份映射异常 | 停止官方新任务 / 动作，启用已演练的配套恢复；检查新增别名是否可向旧版本兼容 | 私域及其它不受影响的通道按原策略继续 |
| 禁言 / 移除等操作成功后才发现配置问题 | 撤销后续权限；报告已知结果 | 不自动反向禁言、拉人或改名单，以免新增副作用 |

Linux + Docker 交付使用构建机预编译产物、服务器解压产物镜像，不在低内存目标机进行完整 SDK 构建。保留上一版本镜像 / 产物、配置与 ID 映射版本；最小健康检查包括进程、连接、无敏感正文的错误计数以及专用测试目标一次明确动作。生产切换、真实群动作、开放管理权限需相应授权；本轮没有执行。

P7 对每项要标为 Accepted 的能力都适用，与是否选择 Webhook 无关。P1–P3 合成检查通过仅表示实现检查完成；缺少适用的 Linux + Docker 或专用官方目标验证时，应标记目标验收待执行。最终按能力逐项签收，例如“文本 / 本人撤回完成，禁言完成，成员移除因内邀延期，Webhook 未纳入”。不能用一项基础聊天成功代替整个官方通道验收。
