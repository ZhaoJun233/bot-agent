## 4. 稳定版本剩余步骤

1. 完成当前集成候选及其回归，按既有脱敏流程发布 dev。
2. 汇总自 1.3.0 以来的对外变化，更新唯一版本源和 CHANGELOG，形成明确的发布候选。
3. 通过 dev → main PR 汇入，遵守当前分支规则；公开 tag 绑定已验证的公开提交。
4. 生成 Linux x86_64 预构建产物，保留回退点，验证目标环境启动、版本与关键路径，完成发布记录。
5. 对剩余事项给出明确边界；实际使用观察需维护者另行恢复后才能继续。
