# 插件解耦执行清单与验收模板

日期：2026-11-14；执行续接：2026-11-17。配套：[总计划](plugin-decoupling-plan-2026-11.md)、[原基线归属审查](plugin-function-ownership-audit-2026-11.md)。状态：R2 实施进行中，D0–D5 和 A01–A39 整体未签收。当前已授权本地实现及合成验证；正式发布、生产部署和真实目标验收仍须各自授权，不沿用此前官方通道任务的外部操作授权。执行记录按候选、切片和原始反例单独保存。

R2 复审新增 A32–A39 及 D0.4、D1.0a/b；它们解决现有实现与独立包目标之间的具体冲突，不是已经完成的重构。

## 1. 开工前必须完成的登记

执行时创建本阶段的资源所有权表，至少覆盖 git 跟踪源代码、路由/DTO、所有配置字段及 env 别名、secret ref、工具、提示片段、定时任务、数据表/文件、前端页/组件、测试、发行脚本。词项扫描只是候选入口，不代替逐项核对。

| 字段 | 必须填写的内容 |
| --- | --- |
| resource | 实际路径与符号/字段/路由，不只写“语音相关文件” |
| currentOwner / targetOwner | 现在在哪个模块，目标 P/S 包 ID；基础设施也要明确归属 |
| readers / writers / callers | 读、写、调用和启动/停止的实际入口 |
| identity / version | 稳定 ID、配置枚举值、schema/程序集/接口版本 |
| origin / effectiveIntent | 预设保留 ID 的可信来源与批准摘要；显式启停/无记录默认值；迁移后意图 |
| contractLoad / dependency | 共享契约装载所有者/摘要、提供者/消费者、精确目标组合、Ready 条件与退役顺序 |
| delivery / activation | 包/宿主/契约版本真源、构建/CI/安装链、只读 UI 资源路径、冷采用或在线采用证明 |
| migration | move / adapt / retain-infrastructure / retire 四选一；说明理由 |
| compatibility | 旧调用者和旧数据怎么读写，适配器删除条件 |
| tests / rollback | 原始反例、执行命令、数据回滚和停止条件 |
| recoveryUnit | 表/文件及跨包事务关联、受影响包、停写/排空范围、共同恢复点、增量写入处理与逐包对账 |
| owner / integrator | 一个直接所有者，一个最终整合者；共享文件需要先登记 |

**完整性门槛：每个旧资源恰好一个所有者；每个旧能力都有目标或明确保留理由。** 应区分“功能从宿主搬走”与“行为被删除”。不能用删除旧路由、关掉失败能力或换成占位 UI 来通过解耦验收。

## 3. 重要的依赖处理

- P04 与 P05：先冻结最小“互动事实/心情建议”接口，不传 MoodStore；P04 可在 P05 缺席时保留现有允许的无心情行为。
- P01/P02/P03 与 S01：先消费当前平台发送端口和提交保护；S01 后续移动实现时契约保持。音频合成不是 QQ 上传，业务包不复制官方预算或重试逻辑。
- P06 与 S04：持久身份、会话删除/授权撤销通知先冻结。画像业务不直接订阅整个数据库或未经授权的会话正文。
- S05 与其他包：只读指标提供者可选；未知状态显式表示，不能把未安装计为故障或强依赖具体类。
- S03 与 S04：保留 QQ 命令/自然对话/Web 任务的独立准入，复用通用执行与回执契约；不强行把尚无等价授权的入口接到同一个“万能 Execute”。
- S01 与 S02：协议层/模型层仅依赖通用数据和端口，不依赖 conversation 的实现，避免“必须先启动对话才能装载平台”的循环。

## 6. 回滚与故障处理

| 失败点 | 动作 | 不允许的做法 |
| --- | --- | --- |
| 发布前 schema/UI/后端校验失败 | 只清理本次候选，保持旧活跃引用、数据和旧 UI；保留失败报告 | 覆盖旧包或临时跳过摘要校验 |
| 持久提交成功但响应/应用失败 | 查询原键回执和 desired/runtime；显示需恢复的应用步骤 | 换键重试、宣称“没保存” |
| 旧代次排空失败 | 阻止后续升级，记录仍在途资源；使用已约定的隔离恢复程序 | 强行卸载仍执行的代码；承诺取消即可撤销外部效果 |
| 数据迁移不兼容回退 | 按预先登记的恢复单元停写/排空，保留增量及其他包的新数据；如必须整库恢复，按明确的组合维护窗口与共同恢复点执行，完成逐包对账 | 把整库恢复当成单包回滚；用旧二进制直接打开未知 schema、清空数据、静默丢新增操作 |
| 前后端指针不一致 | 禁止业务写入、恢复兼容包/UI 对；保留原操作查询路径 | 用新版前端向旧接口猜参数 |
| 副作用结果 Unknown | 保留原收据/序号/作用域，停止自动重放；人工只按证据判定 | 把 Unknown 改成失败以触发自动再发 |
| 新磁盘格式不支持旧宿主 | 在降级切换前拒绝，或使用已验证的兼容组合及状态恢复；保留未知包原字节和旧操作 | 直接启动旧宿主并希望它跳过新字段；删除 Pending/Previous 以让解析通过 |
| 精确依赖组合采用失败 | 停止整组新调用；提交前保持旧组合，提交后先查原回执与 desired/runtime，决定继续或受控回退并关联原记录；核对受影响包、资源和增量状态 | 宣称已提交变更未发生；Unknown/排空失败时自动重启旧组合；只回退供方或松开检查发布中间态 |

每份候选保留：前后端包摘要、契约/配置/数据版本、前一组合锁文件、配置及可恢复状态快照、正在执行/未知操作摘要、迁移日志、恢复命令与实测结果。备份或恢复只针对核对过的路径；记录形状/计数/哈希，不导出私密正文。
