# Agent-03：模型调用与思考参数迁移（Why / What / How）

> 修订：2026-10-07，第二版；Wave 2B。
> 状态、准入、写权及证据见[执行总纲](00-orchestration-and-dependency-graph.md)；先获代码任务授权。

## 一、为什么（Why）

模型传输应能独立演进，但工程拆分不能改变当前调用参数、流式响应、预算、超时和错误处理语义。Model 工程已有解析代码，不代表宿主已经使用它。

## 二、做成什么样（What）

- Model 仅引用 Core；经端口使用外部 IO，Platforms 与 Model 不互相引用。
- 先盘点 Core 的模型端口、现有 OpenAiClient / ModelTransport、图像下载和宿主组装，不复制第二条主调用链。
- ThinkingBudgetResolver 以当前源码为迁移基线，覆盖 none/off/disabled、low、medium、high、xhigh/max、自定义数值及非法输入；不要复制旧文档里已经不完整的映射函数。
- 对当前明确选择的 none 语义，不因默认值过滤而漏掉报文字段；“字段透传成功”不等于所有供应商都会关闭思考。
- 供应商/模型支持差异在适配层定义；未知组合报错或按已批准策略处理，不悄悄转换能力。
- 图像下载保留 SSRF 防护、大小上限和取消；多模态兼容与传输解耦分别验收。
- 秘密与原始模型报文不进入公开诊断；只报告安全错误码、耗时及使用量。

## 三、如何实施（How）

1. 对照旧实现与独立 Model 工程，列出重复类型、参数映射和调用方。
2. 与 01/04/06 确认模型端口、配置来源和迁移顺序；缺口经 00 批准扩展。
3. 使用合成上游记录请求形状，验证字段省略、显式 none、令牌预算及流式解析。
4. 通过 00 合入宿主接入补丁，证明一次实际合成请求走新 Model 实现；通过后再清理旧实现。
5. 运行适用基线及专项故障场景，记录新旧语义差异和兼容方案。

写权：Model 内认领文件及获交接的旧传输文件。宿主、项目引用、网络端口的跨模块移动由 00 协调；不能靠放宽出网安全策略解决依赖问题。

## 四、验收与停止条件

- [ ] S21 与参数边界测试重新执行，实际请求包含预期字段，不只测试纯函数。
- [ ] 主模型与轻量回复模型路由、工具响应、空响应及流式结束语义保持兼容。
- [ ] 认证失败、限流、网络超时、调用者取消与畸形响应有可区分结果。
- [ ] 超时/重试不造成无限调用或未经允许的重复副作用。
- [ ] 宿主采用新实现，安全及适用 SSRF 回归通过；未测供应商如实列出。

采用总纲的退出码检查和先构建宿主流程。供应商协议不确定时先查其官方资料或请求样例契约，不能猜参数，也不能以线上真实会话试探。
