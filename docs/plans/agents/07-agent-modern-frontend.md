# Agent-07：独立 Web 与 Beta 用户验收（Why / What / How）

> 修订：2026-10-07，第二版；Wave 6。
> 状态及写权见[执行总纲](00-orchestration-and-dependency-graph.md)。
> 仅在完整后端及 ZBA 验收、00 核对和负责人明确解锁后开工。

## 一、为什么（Why）

独立面板围绕“看状态、改配置、让 Agent 干活”，避免前端猜接口或用模拟成功掩盖后端缺口。前后端分离是开发/发布边界，不是拆出额外后台进程。

## 二、做成什么样（What）

### 2.1 输入

- 通过验收的 ZBA OpenAPI、后端版本、认证方案及安全合成样例。
- [面板规划](../z-bot-panel-v0.1-beta-plan.md)中的首版冻结范围和三条用户主线。
- 由 00 登记的 Web 开工批准；接口未实现或契约与实测不符时退回 06，不硬编码临时路径。
- 拟建 web 独立目录和独立产物；前端框架/组件库/包管理器在此阶段评审，旧文档中的 Vue/React/Vite/Tailwind 不构成已选型事实。

### 2.2 用户体验

| 主线 | 必须表现 |
| --- | --- |
| 看状态 | 区分可用、停用、待配置、故障；未知与加载中不是成功 |
| 改配置 | 明确未保存、已保存、已生效、需重启；字段错误、版本冲突可恢复 |
| Agent 任务 | 展示动作摘要、工具名称、安全结果摘要、审批与真实终态 |
| 取消 | 请求中、确认取消和结果未知不同；不能点击后就写“已取消” |
| 恢复 | 刷新/断线后查询任务或恢复事件；不得重新发起原工具动作 |
| 隐私 | 列表显示脱敏、内部 key 保留；可编辑真名用 nameRaw，不写回占位名 |

统一保存条提交同一份草稿和基准版本，经后端整批校验。不得用循环调用多个分区接口冒充一次原子保存；冲突时让用户比较/重载，不静默覆盖。

不展示模型隐藏推理；工具详情采用后端允许的安全摘要，不默认展开原始入参和返回。可解释性来自实际动作与结果，而非推理文本。

### 2.3 范围限制

- MCP 管理页只有经负责人明确纳入本次 Beta、且对应契约已验收才开发；否则从导航与“已支持”承诺中移除。
- 第三方市场、Docker 高权限管理、任意容器创建和远程部署不自动纳入首版。
- 旧 P1/P5/P6/P7、V1–V3 编号只作为历史线索；实际需求写成移动端可操作、未保存保护、键盘可达、弹窗焦点/关闭和错误恢复等可测行为。
- 不在后端契约冻结前规定事件流路径、开发端口、返回字段或组件名；SSE 是否启用以契约为准。

## 三、如何实施（How）

1. 核实准入证据与范围，确认框架/包管理器和 API 基址策略。
2. 建独立工程并记录真实安装、测试、构建命令；客户端从冻结契约生成或按契约实现。
3. 先打通状态、保存、任务三条最小真实链路，再补交互与视觉；开发 fixture 明确标为合成数据，不混入演示成功状态。
4. 完成认证/会话失效、未保存、冲突、取消及刷新恢复，验证桌面、移动端与键盘。
5. 将静态产物独立发布；同源代理或跨域配置由 06 提供方案，00 合入共享部署文件。
6. 提交前后端版本兼容、用户场景与回归证据，等待负责人批准 Beta 使用。

写权：web 内认领路径；现有前端探针、CI 和部署文件先登记交接。测试脚本依据真实 DOM/组件与浏览器行为更新，不以扩充到固定断言数量为目标。后端缺陷由相应负责人处理，07 不绕过授权或直连数据库。

## 四、验收与停止条件

- [ ] 独立构建/发布，前端改动无需重新编译后端；使用冻结 ZBA。
- [ ] 三条主线的成功/失败/未知状态与真实后端结果一致。
- [ ] 切页、刷新、弹窗关闭保留或明确丢弃草稿；冲突不静默覆盖。
- [ ] 权限、秘密不回显、脱敏及 nameRaw 编辑回归通过。
- [ ] 移动端、键盘、焦点、错误重试与事件恢复通过浏览器测试。
- [ ] 后端和 Web 兼容版本、测量和回退证据齐全；未覆盖项明确列出。
- [ ] 负责人按门禁决定使用日期；2026-10-10 至 2026-10-11 不代替验收。

总纲提供通用退出码和证据规则。web 工程尚未落地前，本手册不提供虚构的 pnpm 或浏览器测试命令；建立工程时必须补齐实际命令后才可交付。
