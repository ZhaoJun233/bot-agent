# Agent-05：MCP 客户端与工具治理（Why / What / How）

> 修订：2026-10-07，第二版；Wave 4。
> 状态、准入、写权及证据见[执行总纲](00-orchestration-and-dependency-graph.md)。
> 等待 Wave 3 验收与代码授权；MCP 管理页延期不免除本波次后端验收。

## 一、为什么（Why）

接入外部工具应复用标准协议，同时保留项目现有权限、出网保护和结果审计。旧版“Remote SSE 或 Docker”“8 秒硬终止”“Sanitize 任意结果”的表达不能直接用于实现。

## 二、做成什么样（What）

### 2.1 协议与承载分开

本轮查阅的 **2025-11-25 版本**规范定义 stdio 与 Streamable HTTP，旧 HTTP+SSE 为兼容路径；Docker 是部署/进程承载方式，不是这两种标准传输之一。[官方传输规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)

该版本要求初始化、版本/能力协商，再进入正常交互。[官方生命周期](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle) 取消有自己的协议语义，不能把本地停止等待等同于远端副作用已撤销。[官方取消规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/utilities/cancellation)

以上是带版本的参考，不声称其为最新版本，也不把其它版本的会话/取消规则混入。**开工前由 05 提交目标协议版本、C# SDK 版本、服务器兼容矩阵与该版本官方依据，00/06 确认后冻结。** 若目标版本生命周期不同，相应更新测试和本手册；没有冻结记录不开始协议实现。

项目首版策略：

- 远程 Streamable HTTP 为首选；旧 HTTP+SSE 仅在已确认兼容需求时增加。
- stdio 仅在显式批准的执行环境纳入，不要求低内存生产宿主启动额外运行时。
- Docker daemon 管理及任意本地高权限承载在 Beta 范围外；不挂载 Docker Socket 来兑现所谓“天然沙箱”。
- SDK 优先于手写协议；选择时确认 .NET 8、许可证、资源预算、取消/释放及可注入出网策略。SDK 不得绕过项目的出网安全边界。

### 2.2 目标结构

拟建 Mcp 仅引用 Core。工具发现和执行通过评审后的 Core 端口提供给 Engine，宿主注入实现；秘密与配置经存储端口获取，不直引 Storage。连接、工具投影、权限治理和失败映射按职责划分，不预先强制不存在的类名。

### 2.3 必须定义的行为

| 层级 | 项目验收要求 |
| --- | --- |
| Server | 稳定标识、显式授权、秘密引用、状态、资源释放；端点/重定向/DNS 变化遵守出网策略 |
| Tool | 工具名命名空间、Schema 校验、能力变更处理、权限过滤；发现成功不等于获得执行权 |
| Call | 参数校验、审批绑定、总预算与单次预算、取消原因区分、结果大小及类型限制 |
| Result | 远程内容按不可信输入处理；审计与脱敏分别调用真实存在的机制 |
| Recovery | 断线、会话失效及重连规则按冻结版本测试；不能自动重放有副作用的调用 |

ReplyAuditRules 当前提供 Judge 判定，不提供旧手册中的 Sanitize。把允许/拦截、显示层脱敏和结果结构校验分开设计；不能用清理字符串替代权限或发送审计，也不能宣称 DLP 能识别所有秘密。

预算可以配置，但必须注明作用域。至少区分调用者取消、预算耗尽、传输失败、工具失败和结果未知；不响应取消的远程动作继续可能产生副作用，应记录未知状态并提供核对方式。隔离等待、限制在途数量并回收本地资源；不以 CancellationTokenSource.CancelAfter 保证远端硬终止。

## 三、如何实施（How）

1. 冻结版本/SDK/传输支持矩阵；先查 SDK 官方接口，提交实现选择和出网策略验证。
2. 与 01/04/06 冻结工具注册、执行结果和安全管理端口。
3. 使用合成 MCP 服务完成版本适配的初始化/能力交互、发现和调用；不连接真实聊天数据。
4. 加入 Server / Tool / Call 治理、错误映射、取消、恢复及停机资源释放。
5. 通过 00 合入宿主接入；经 Engine 调用验证权限和审计，不止直接测试客户端。
6. 提交协议互通结果、资源预算及不支持的能力；通过后再请求 Wave 5 集成验收。

写权：Mcp 内认领路径及已分配的合成测试；Core 契约由 01/00 协调，Engine 接入由 04 配合，宿主等共享文件由 00 合入。

## 四、验收与停止条件

- [ ] 冻结版本和实际请求一致，支持/拒绝的能力都有测试。
- [ ] 工具发现、Schema 边界、未知工具、越权调用和秘密不回显通过。
- [ ] 调用者取消与超时不同；不响应取消、结果过大及畸形结果不拖垮主会话。
- [ ] 重连不重做副作用，停机后本地连接与任务按预算收口。
- [ ] SDK 流量仍符合 SSRF/认证边界；失败不会降级成不受控外连。
- [ ] 总纲适用基线及实际新增的 MCP 合成契约测试通过。

没有版本冻结、不能治理 SDK 出网或需要 Docker 高权限才能推进时，停止并交负责人确认，不偷偷扩大首版范围。
