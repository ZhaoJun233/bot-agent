# Agent-02：平台适配与生命周期（Why / What / How）

> 修订：2026-10-07，第二版；Wave 2A。
> 状态、准入、写权及证据见[执行总纲](00-orchestration-and-dependency-graph.md)；先获代码任务授权。

## 一、为什么（Why）

把 OneBot、官方平台、飞书和本地通道的通信细节与回复主干隔离，同时保留各平台真实能力和权限差异。已有 Platforms 工程不等于全部运行链路已验收。

## 二、做成什么样（What）

- Platforms 仅引用 Core，平台传输不得反向依赖 Headless、Model 或 Storage 的实现。
- 优先复用 IPlatformAdapter、IPlatformMessenger、IPlatformRegistry；旧手册的 IPlatformDriver / OneBotDriver 是设计示例，不是当前实现名。
- 缺失的生命周期/管理能力与 Agent-01 协商扩展，描述未配置、连接中、可用、停用、错误等状态；状态枚举和错误码评审后冻结。
- 平台身份、实例范围、会话 key 与白名单保持隔离；官方/飞书别名映射兼容现有存储。
- 连接状态、启用平台、启用聊天、凭据就绪和白名单分别判断；不能因为“已连接”而开放聊天。
- 不支持的媒体或管理动作显式拒绝；不把全部能力标为 Full。
- 秘密不进入状态 DTO；列表显示遵守脱敏，内部标识保持原样。

## 三、如何实施（How）

1. 盘点现有四类通道、收发端口和平台策略调用点；列出已迁移与仍在旧目录的文件。
2. 与 01/06 冻结管理契约和实例标识；保留旧消息及配置格式，明确迁移策略。
3. 按平台逐条迁移，确认宿主的收消息 → 权限/策略 → 回复 → 发消息确实经过新实现。
4. 验证连接生命周期、失败重试、取消与停机；重连不能重复订阅事件或重复发送消息。
5. 合成回归通过后提出旧文件清理和共享文件补丁，由 00 合入并核对接入。

写权：Platforms 内认领文件；对旧网关文件逐文件交接。解决方案、宿主引用、设置、公共测试入口不自行改写。

## 四、验收与停止条件

- [ ] 四个平台分别有发送、拒绝及不支持能力测试，不仅验证程序集构建。
- [ ] 启用/聊天/白名单/凭据组合、实例隔离和状态恢复符合现有约定。
- [ ] S52 及现有 FeishuRemediationProbe、ReverseTransportProbe、SettingsScopeProbe 等适用测试重新执行，记录实际覆盖。
- [ ] 断线重连不重复处理，关闭/重启后无悬挂订阅或任务。
- [ ] 宿主接入及向后兼容有证据；官方通道未跑的端到端场景明确列为未覆盖。

通用命令流程见总纲；专项工程名称与入口执行前核实。缺少必要测试时先补合成测试，不能用真实群聊试。不得为了本任务启动第二个使用同一账号的协议端；需要生产验证时单独申请具体操作。
