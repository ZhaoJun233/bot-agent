## 1. 目标与基线

基线为公开 dev 35de38d766f205348dffd51640a44176b1775253，tree d47fa6335c46078443574e5979f5e3e3c78a7ceb。继续使用 .NET 10 + Vue + Python 扩展、独立 Web、单宿主模块化单体；本次不引入每个插件一个微服务的部署体系。

**目标：同一个功能的业务逻辑、工具、提示词、配置、后台任务、数据访问与迁移、管理接口、前端和测试，都由该功能包拥有；主体只负责通用装配、安全和运行基础设施。**

现有 7 个预设只是元数据壳，不能直接打 ZIP 就算完成。最终安装、升级或卸载一个功能包，不应要求编辑 ReplyPipeline、PromptBuilder、AppSettings、ZbaClient、CapabilitiesPage 或 CompositionRoot 的该功能分支。默认发行版仍可预装功能包，不意味着用户每次都要手动安装。

### 完成标准

1. 包目录能独立构建后端、前端、契约和测试，发行归档绑定相同版本及摘要。
   “独立更新”指无需修改或重建主体业务代码，不等于所有功能都可热替换；包可明确要求宿主重启，界面应如实显示采用方式。
2. 以搜索和配额两个迁移样板分别证明工具/上下文与自定义管理页面两类扩展；完成通用接入后，继续调整样板业务时宿主通用代码零业务改动，预装清单及生成锁文件可以变化。
   D5 再以未预装 ID 的两个合成测试包验证发现、安装、调用、页面、升级和卸载，排除仅对样板 ID 硬编码的实现；这些是测试夹具，不新增产品业务。
3. 移除任一非基础包，主体仍能启动，管理页可说明缺失依赖；已移除功能没有隐藏定时器、残留路由或第二份执行者。
4. 不改已冻结的用户语义、权限默认值、会话 key、平台 ID、工具 ID、配置枚举值、secret ref 和 Unknown/不可重放语义。
5. 当前 8 个预设及 5 类系统功能逐项有前后端、配置/数据、关闭/升级/回滚与入口验收。只完成首批样板不等于全计划完成。

## 2. 归属边界

| 留在主体/公共基础设施 | 聚合进功能包 |
| --- | --- |
| 进程启动、依赖装配、停机、包目录与版本选择 | 自身后端实现、资源创建/释放策略、声明的依赖 |
| 身份认证、权限裁决、来源与工具租约、通用提交保护 | 功能的准入条件、作用域需求和操作声明；只能进一步收紧权限 |
| 配置版本/事务协调、幂等回执、审计、秘密代理 | 配置 schema、默认值、校验规则、应用动作、UI 文案及旧字段映射 |
| 数据库连接/事务/备份协调、受控文件及网络设施 | 本功能的数据模型、repository、迁移步骤、保留/清理规则 |
| 通用调度器、资源额度、时钟、指标收集 | 任务内容、触发策略、任务状态、功能指标定义 |
| 统一事件与操作分发、通用 Web 壳、认证和页面容器 | 路由处理、DTO/schema、页面/组件、帮助、提示词、静态资源 |

“功能聚合”是代码及知识归属，不要求每个包建一套数据库、HTTP 服务或认证系统。业务 repository 通过受限事务设施访问本包资源；不能导入 Headless、绕过事务协调，或查询其他包的私有表。

### 2.1 包的最终组织

下列目录为**拟议目标**，并非当前已存在的接口或文件：

~~~text
plugins/<stable-plugin-id>/
  package/          # 版本化清单、依赖、摘要、兼容范围、默认启用意图
  contracts/        # 本包公开输入/结果/schema，保持小而明确
  backend/          # 业务、工具、上下文贡献、协议适配或管理处理
  configuration/    # schema、默认值、校验、旧字段映射、应用步骤
  storage/          # 自有数据访问、迁移与恢复说明
  web/              # 页面/声明式表单、文案、资源、构建入口
  prompts/          # 本功能模型指令和结构化输出声明
  tests/            # 契约、单包、升级、UI、入口用例
  docs/             # 使用、运维与兼容说明
~~~

目录先聚合到同一仓库，形成独立构建和版本边界；无需同时拆多个 Git 仓库。真正无实现的目录不创建空壳。目标包可有内部子模块，消费者只跨公开契约，不能绕到其内部类。

### 2.2 依赖方向

~~~mermaid
flowchart TB
  Host[宿主与 Web 壳] --> Runtime[通用插件运行时与能力目录]
  Runtime --> Contracts[公共契约与安全设施]
  Runtime -.按清单加载.-> Packages[功能包：后端 / 前端 / 配置 / 数据 / 测试]
  Packages --> Contracts
  Packages -.显式依赖的公开契约.-> Providers[其他功能包公开能力]
  Packages --> Ports[受控存储 / 网络 / 调度 / 模型 / 平台端口]
  Ports --> Infra[通用基础设施实现]
~~~

禁止：Host 直接引用功能具体类、插件引用 Host/另一个插件私有类、前端插件直接导入主体 ZbaClient/App 状态、插件拿全量 SettingsBox/IServiceProvider、同名工具覆盖、隐式循环依赖。

依赖清单描述必需/可选、版本范围与能力要求，并在采用时解析为不可变的精确版本/摘要组合。必需依赖必须运行可用才允许依赖者激活，不能只检查磁盘上有 Active。可选依赖缺失给出明确降级。消费者先排空、提供者后退出；卸载仍被依赖的提供者时返回依赖者清单，不静默级联删除配置。

现有依赖是精确版本，尚非版本范围解析器。D1 保留它的旧语义并设计组合切换：例如消费者 C1 精确依赖 P1，升级到 C2/P2 时，先更新 P 会被旧反向依赖挡住，先更新 C 又缺少 P2。必须先校验整个目标组合和受影响范围，准备全部产物，再一起停写/排空和采用。提交前失败保留旧组合；持久提交后响应丢失或激活失败，保留原组合回执和 desired/runtime 差异，依据恢复流程决定继续或回退，不把已提交状态改称未发生。排空失败或副作用 Unknown 不自动重新激活旧组合。组合的业务入口只有在必需成员均 Ready 后统一发布，中间状态只在管理诊断中显式展示。不能靠临时放松版本检查跨过中间状态；运行调用只经带代次租约的代理，不缓存提供者具体实例。

## 3. 现有机制怎么复用，哪里要补契约

以下是设计需求，不宣称已有对应扩展方法。D1 以真实样板冻结最小签名，所有新接口必须同时有生产适配器与测试替身；不先设计万能插件 API。

| 贡献面 | 复用的现有机制 | 必须补足的语义 |
| --- | --- | --- |
| 工具执行 | ToolSpec、ToolVisibility、IToolExecutor、权限与来源租约 | 工具声明及真实执行者由包同代发布；替换聊天 LegacyPath；重复 ID 拒绝；持有者/实例/代次可追溯 |
| 回合准入 | IReplyPolicyPlugin、PluginReplyPolicies | 保留排序、异常安全及退役保护；有副作用的异步步骤不塞入同步 BlockReason |
| 上下文与提示 | 现有回合、记忆授权、模型预算接口 | 包返回受限结构化贡献，声明来源、可见范围、过期及字数预算；按阶段/依赖/稳定 ID 排序，冲突拒绝，不传完整会话存储 |
| 入站附件 | 平台规范事件、来源证明、官方引用链 | 只给本次获准的附件句柄；有生命周期、大小与用途限制；引用与发送关系可追溯；严禁旁读 DB、重开协议端 |
| 输出/投递 | ReplyCommitBoundary、平台发送端口、可靠回执 | 功能只提交授权后的动作意图；业务呈现归包，提交前再次检查活跃来源/权限。超时或 Unknown 不换 operationKey/seq 重放 |
| 配置 | ConfigurationStore、SettingsHotReload、PluginSettingsStore | 插件拥有 schema/应用逻辑，基础层拥有版本及事务；历史配置路径是兼容投影，不能形成第二个可写真源 |
| 管理与前端 | ZBA 认证、操作恢复、ManagementDialog、声明式设置 | 通用按包分发；后端和前端 schema 同代；自定义页面随包安装，界面刷新不丢未决操作 |
| 生命周期 | Package Active/Pending/Previous、PluginManager 租约/排空 | 将租约覆盖工具、页面会话、后台任务、上下文贡献，不只覆盖策略回调；分清激活/可用/禁用/排空状态 |

### 3.1 工具、提示与模型的拆分

- 工具 ID、参数解析、结果解释、提示片段和执行者同属包。Model 只认识通用模型消息/结构化输出，不再定义 MusicText、VoiceEagerness 等业务选项。
- conversation 包负责回合顺序、上下文总预算、通用工具循环及回复节奏；包贡献须有明确阶段、超时、取消、失败策略、只读/副作用声明。不能用一个任意顺序事件总线替代现有确定流程。
- 迁移期间旧 JSON 输出字段通过单向兼容解码映射到同一操作；同一轮只能选择旧执行或新执行。影子比对只允许纯计算，绝不对真实发送、扣费、写库双跑。
- PluginGate 对未知名称放行与 ToolVisibility 对未知工具拒绝的现有组合不可被“统一布尔开关”误改；最终对每个已登记操作验证确切所有者、工具声明、启用状态和平台能力，兼容分支有删除阶段。
- 语言模型/provider 协议仍由 model-services 提供，音乐分析与画像摘要声明所需模型用途并接受预算，不能通过全局配置任意切到其他凭据。

### 3.2 页面与接口的完整聚合

最终默认路线：简单设置继续使用包内声明式 schema；复杂页面由包自身构建静态资源，通过通用页面容器与受控管理桥接使用。内置和外部包使用同一描述机制。

1. plugin-settings.ts 的逐插件表迁到包内；宿主只发现描述、验证冲突和渲染。TokenQuotaDialog、平台专属诊断、ProviderEditor、TasksPage 等随所属包迁移。
2. 通用表单、模态焦点管理、脱敏显示、认证会话、原键找回和未决操作保护留 Web 壳。包不能拿 bearer、直接写全局草稿或把 nameRaw 替换成脱敏显示值。
3. 自定义 UI 使用受限 iframe/消息桥接的目标方案：不开放父页面 DOM，不给同源权限或任意宿主服务；绑定窗口来源、一次性通道标识、用户会话、包 ID/版本/代次；校验每个操作的 schema 和权限。限制脚本/网络来源、导航和资源规模，禁止任意远程入口及 service worker。具体 CSP、资源路径和桥接签名在 D1 冻结。
4. 静态资产的 hash、UI 契约版本和后端版本绑定。后端未就绪/版本不匹配时不启用写操作，明确显示原因；用户打开旧页面时升级不能把旧请求转给新语义。未决操作仍可按原键查回执，不重复提交。
5. 过渡期可由发行构建收集各包的前端资源，但**最终需要升级单包不重建主体前端**。运行时 UI 交付门槛未通过，整项就仍未完成。
6. 新功能只走版本化 ZBA 扩展面；不扩充冻结的 /api/*。旧业务路由保留兼容转发至包的同一处理者，缺包安全失败，逐项按兼容周期退役，不偷偷删现有功能。

### 3.3 配置、数据、身份的迁移

- 冻结既有插件 ID、工具 ID、平台 ID、会话 key、配置字段枚举和 secret ref；引入包所有者元数据，不借重构改名或改变默认行为。
- 对每个旧字段登记：当前真源、读取者、写入入口、默认值、环境覆盖顺序、目标包、应用代次、回滚方法。一次配置事务仍由现有协调器执行，插件提供校验及待应用投影；共享锁内不执行插件外部代码。
- 旧字段与新包设置在过渡期只有一个写入所有者。提交后返回 durable receipt；运行应用失败明确显示 desired/runtime 差异，不把持久提交伪装成回滚。
- 数据表和文件先原位保留、迁移代码随所有者搬迁；确需变 schema 时用可回读的扩展迁移、迁移日志、快照和中断恢复，禁止重编号或清空旧 key。
- 官方 openid 类型、所属应用/群、出站消息证明、引用链、被动额度和 seq 属于官方平台包；跨包只传通用不透明身份/回执，不能把底层字段复制到通用会话业务。
- 跨模块原子变更由通用事务协调；文件+SQLite 无法自动获得原子性，采用暂存、日志、发布点和重启恢复并写清失败状态。不要以拆包为由创建第二套数据库协调器。
- 每次迁移先定义最小恢复单元：涉及的表/文件、事务关联、受影响包、停写与排空范围，以及迁移期间增量写入的保留/重放限制。共享 SQLite 的整库备份不是单包回滚；不能恢复一个包时覆盖其他包的新数据。无法按包恢复时，必须事先声明组合维护窗口、共同恢复点与逐包对账方法，禁止带着该缺口切换候选。
- 卸载默认保留配置、数据、历史回执、Previous 和已记录的禁用意图。彻底清理是另一个明确操作；重装不能意外启用，也不能重放原来 Unknown 的动作。

### 3.4 生命周期、资源与兼容

- 保持已存在的候选准备、持久化、原子引用发布、旧租约排空、Shutdown 顺序；每类新回调都必须参与相同的代次管理。
- 后台任务只用注册到运行时的任务/计时器/受控工作进程。禁用立即拒绝新工作，在途任务按契约取消/收尾；不能把关闭卡片当作资源已释放。
- 超时排空失败时记录真实状态并停止进一步升级，保留可恢复包及证据；不声称 CancellationToken 可以杀死任意插件线程，也不因超时重新提交外部副作用。
- .NET 仍是受信任的进程内代码；Python 独立进程与页面 iframe 也不等于整套后端安全沙箱。现有维护者审核、包内容审计与权限裁决继续生效。
- API 1 的 .NET 包、API 2 的 Python 包保留独立兼容适配器。若抽出 PluginContracts 程序集，先验证类型身份、程序集版本、类型转发及旧二进制加载，不能只改 namespace 后宣布兼容。
- 新 manifest 不复用旧 ApiVersion 含义；清单、后端契约、UI、配置与存储版本分别识别。旧宿主明确拒绝不支持的新包；已安装旧包不会因新能力字段缺失被静默损坏。

### 3.5 保留 ID、恢复入口与持久状态

**内置预设搬成包需要专用迁移路径。** 当前外部包校验拒绝 preset.*，已注册 IsPreset 也不能被包替换。D1 先增加由默认发行组合及批准摘要证明的内置来源身份，只有它能迁移原 ID；来源证明由宿主核验，不能由包自填“内置”字段取得。外部导入仍拒绝保留命名空间。同一 ID 的旧预设与新包只存在一个活跃注册；迁移记录可在中断后判定继续或回退，不把冲突当作一次普通覆盖。

首次迁移先捕获旧 effective enabled：显式 true/false 优先，没有记录则按旧预设默认值，再保留各 enableFeature 与平台策略的组合。随后写入迁移后的显式意图。不能删掉 _presetIds 后把“原来默认开启”误成新外部包的默认关闭；全新外部安装仍按现有规则默认禁用。

**恢复入口必须先于业务图可用。** 宿主的认证、包目录/安装与修复、最小配置、健康与诊断、通用操作回执查询不依赖模型、Agent、conversation 或某个平台成功初始化。业务处理器按已就绪包注册；缺包返回明确不可用，不能用假对象伪报 ready。认证失败本身不在此保证内，恢复入口不绕过鉴权。实现顺序先切开构造依赖，再证明无包/坏包可进入管理界面，最后迁业务。

卸载或损坏的包仍可能有旧操作：通用回执保留稳定的归属、调用范围、请求摘要、契约/代次和终态，基础界面能按原键读安全状态。业务结果解码与存储仍属包；没有兼容解码器时说明不可展示细节，不执行旧插件代码来“恢复状态”，也不把未决/Unknown 操作自动重提。

**宿主降级不同于插件回退。** 当前严格解析器会读取 Active/Previous/Pending 内的完整清单；写入新版字段后，旧宿主可能连 Previous 都读不了。D1 必须把用于目录/恢复的稳定状态信封与执行清单分开，登记磁盘格式与最低可读宿主版本；按包隔离未知/损坏条目并保留原字节，不能一个坏条目拖垮所有包的目录与恢复列表。降级前先检查将启动的宿主能否读取整套状态；不兼容则在切换前拒绝，或在已批准维护窗口恢复已验证的兼容组合/状态。不得声称旧二进制能自动理解新格式，或通过丢弃新字段伪造兼容。

### 3.6 跨包契约和批准范围

当前加载器只共享 IBotPlugin 所在程序集，其他 DLL 各包单独载入。两个包各带同名 contracts DLL 仍可能产生不同类型身份。D1 对每个跨包契约声明唯一装载所有者、版本兼容范围和摘要；同一契约由宿主协调的共享契约上下文提供，业务实现和可并存的私有依赖仍留在各自上下文。契约有活跃消费者/租约时不卸载，升级契约需要采用整个受影响组合。若某条边改用序列化消息，也必须明确 schema 与错误语义，不能把反射或任意服务查找当成类型兼容方案。

新增 UI 入口、资源摘要、贡献权限、配置/数据版本及激活方式，必须同时进入清单校验、规范化表示、后端预览/指纹、前端差异展示、批准绑定、持久包状态和操作回执。当前这些路径存在手写字段投影，仅扩展 parser 不够。D1 建立逐字段覆盖表；每次只改一个安全相关字段，旧预览/批准均失效。规范化应对无语义的字段顺序稳定，对任何执行语义变化敏感；版本号未变也不能沿用旧批准。

### 3.7 构建发行与采用方式

当前 Directory.Build.props 和 CI 把宿主版本作为全仓唯一版本，直接在包工程另写 Version 会被拒绝。D1 先将版本规则分成宿主、包发行、共享契约三种明确归属，每种仍有一个真源；同步精确修改构建/版本护栏，保留宿主 tag/CLI 一致性、确定性构建和依赖审计，不通过删除检查解锁。包依赖和契约摘要进入组合锁文件；共享契约升级需要验证所有受影响消费者。

发行链登记从包源码/构建入口到 ZIP、宿主组合清单、容器挂载与实际装载摘要的每一步。新增工程必须进入解决方案/CI 与全包结构扫描；独立后端发布和 Web 资源收集都不能漏掉包文件。干净 checkout、无本机缓存、无服务器编译的 Linux 产物安装必须能跑通；所需托管库/资源及有声明的运行时依赖都包含或明确由已校验运行环境提供。

独立 Web 壳保持现有部署职责。D2 在包资源提供者与 Web 容器之间冻结资源交付契约：已批准包/版本/hash 对应的只读资源根、URL/访问规则、原子发布点、旧资源保留期和失败恢复。资产字节与批准摘要一致；缺失文件返回缺失而非登录页或主页面，旧页面/在途回执仍可完成恢复。安装完成必须在真实 HTTP 页面打开包资源验证，不能只检查 ZIP 里有 web 目录。

当前候选准备会调用 InitializeAsync，然后才替换旧实例。迁入平台后若初始化立即联网，可能新旧协议端同时连接。新贡献面须声明冷采用或可在线采用：含协议登录、监听端口、定时发送等独占资源的包默认要求冷采用；只有证明准备阶段不产生外部副作用、旧所有者排空后才激活新所有者，才开放在线采用。D2 提供机制，D4 逐平台验证。现有旧扩展保持原生命周期 ABI；无法安全拆开其初始化行为时不宣称支持新在线模式。

## 4. 全量迁移顺序

按完整行为切片推进，每阶段都涵盖前后端及数据；不是先把所有后端搬完、再统一补界面。

| 阶段 | 范围与依赖 | 交付物 | 退出门槛 |
| --- | --- | --- | --- |
| D0 所有权与准入 | 在本次审查上锁定候选、全量资源所有者和待迁移契约 | 13 个工作项加平台子包/MCP/记忆等明确拆分；资源、恢复单元、保留 ID/默认值、构建发行和控制入口登记；初始运行基线 | 无无人认领的业务资源；复审 A32–A39 各有负责阶段；保留旧反例；不把源码读取当成运行验收 |
| D1 最小通用契约与样板 | D0；先 Token 配额，再联网搜索，覆盖策略+状态/页面和工具+模型贡献两类需求 | 版本化包描述、受控配置/操作/任务/上下文接口；两个完成代码归属与后端边界的样板；包内简单表单与复杂页面，由过渡发行构建收集 | 完成初次迁移后，样板业务变更不再修改核心业务文件；无双执行；旧插件兼容；用户确认实际页面变化。UI 运行时独立升级留待 D2，D1 不宣称整包独立交付完成 |
| D2 扩展前端与完整包生命周期 | D1 | 自定义 UI 资源交付/消息桥、同代目录、依赖组合采用、冷/在线能力区别、禁用/升级/卸载/回滚 | 单包升级不重建宿主前端；真实 HTTP 可打开新包；版本错配拒写；旧 UI 能找回原操作；故障/中断恢复通过 |
| D3 迁移剩余六个预设 | D1+D2；顺序戳一戳→氛围→表情→音乐→语音→画像 | 每个包自己的实现、提示/工具、字段/UI、状态/任务、tests | 每包无包运行与主体零业务改动；高风险投递、隐私、记忆与旧回执回归通过 |
| D4 系统功能聚合 | D3；先健康报告→模型服务→Agent/MCP→对话策略；平台子包在上述公共协议稳定后逐个迁 | 五类系统功能及平台子包独立交付；对话编排不认识预设实现；统一指标替代报告的业务对象依赖 | 主体只剩通用运行；平台/模型/任务入口分别验证，未选能力保持原状态 |
| D5 清除兼容债与验收 | 全部包完成且兼容观察达标 | 删除无调用旧分支/重复目录；发布组合清单；测试、升级/回退操作手册、最终依赖报告 | 全清单签收；新旧反例保留；Windows/Linux Docker、浏览器与获准真实入口验证；发布/部署单独授权 |

D3 的画像可以等待记忆授权契约，不能用访问全库来赶进度。D4 内平台包可提前做只读协议清单及契约设计，写入迁移仍按单个所有者串行。工期不凭目录数量估算：D1 的两个完整切片得到实测成本后再排日历，任何阶段不得凭日期跳过退出门槛。

D1 新贡献面的每个实际调用，在启用前就必须取得代次租约并执行准入；这部分不能拖到 D2。D1 样板只以停止宿主、排空、校验、切换组合后重启的方式安装/更新/移除，不开放尚未验证的在线替换。禁用立即拒绝新调用，在途调用按租约收尾。D2 才开放新贡献面的在线升级和自定义 UI 运行时替换，并补全页面会话等新增资源的生命周期。这个阶段限制不改变现有旧包已支持的生命周期语义。

## 5. 必须保持的行为与安全不变量

1. 插件未注册/禁用/来源过期/权限收回后，新的发送、上传、模型调用和后台任务按现有契约拒绝；最终提交前实时复查，不能只在工具列表显示时检查。
2. 包声明、安装成功、连接正常、界面可见不代表平台授权。官方受限管理/Markdown/按钮能力继续是 Deferred，迁移不扩大当前许可。
3. 业务执行结果保留 Success/Rejected/Degraded/Unknown 及原始关联；Unknown 不自动降级重试，不产生新序号冒充新请求。
4. 配额停用不停止通用用量记账；画像停用不开放更多存储；报告停用不关闭基础健康检查；conversation 停用不禁用管理、审计或平台协议安全。
5. 不读真实群聊验证结构；测试只用合成身份/内容。真实 QQ 验收只有在明确授权的目标和动作范围内另行进行；历史授权不自动扩大到本次重构。
6. 秘密只通过引用及作用域代理，日志/接口不回显；展示掩码不修改存储 key，编辑使用 nameRaw。
7. 网络、文件与进程能力有资源边界，包之间依赖与审计可追踪；不以新增 service locator 消除编译引用来伪造解耦。

## 6. 收口条件与交付边界

执行表每行有一个整合者，代码所有权与共享文件变更明确登记；不得并发修改 Core 契约、事务协调、CompositionRoot、ZBA schema、公共前端注册器或测试入口。允许实现阶段按模块分工，最终集成串行；本计划不自动启动任何施工。

旧 architecture 数值阈值只降不升。新增包工程的精确依赖规则应增强护栏；不能把全部新目录排除扫描，不能把合法来源列表泛化成任意插件可以引用所有业务工程。目录搬出 src 后仍须被新的全包扫描覆盖。

最终报告要同时回答“源代码是否聚合”“实际宿主是否采用”“原入口行为是否保持”“单包是否可更新回退”。任一项缺证据就标未完成；源码目录、包文件数量或 CI 绿灯不能单独替代完整验收。
