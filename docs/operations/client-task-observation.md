# 导出本次 Web 任务统计

在「Agent 任务」页展开「本次任务统计」，选择「导出本次统计」。下载的 JSON 记录当前客户端连接发出的任务提交，以及正常回读时观察到的状态。导出不会提交任务、触发模型调用或额外查询服务器。

计数从建立当前连接开始。离开任务页再返回仍属于同一客户端；刷新页面、锁定后重新连接或更换身份会建立新集合。它不保证后台持续跟踪，也不跨刷新保存。准备留存观察材料时，应在结束连接前导出，并单独记录使用的前端版本、宿主候选、配置版本、入口和任务类别；文件本身不能证明这些归属。

## 计数的含义

| 字段 | 含义 |
| --- | --- |
| attempts | 已登记的提交调用次数，在发出请求前登记 |
| accepted | 当前集合内确认受理的唯一任务数 |
| acceptedReplays | 同一意图取得相同任务的额外确认次数 |
| rejected | 按现有客户端规则明确拒绝的尝试 |
| acceptanceUnknown | 无法确认是否受理的尝试；超时、断网及不确定响应保留在此 |
| awaitingAcceptance | 请求仍在等待结果的尝试 |
| untrackedAttempts | 超出 512 次容量后未登记的尝试；已有记录不被挤掉 |
| acceptedCohortComplete | 仅表示本客户端集合无未登记、待定、受理未知或观测故障；不证明全服务受理集合完整 |
| states | 已确认受理集合中最后观察到的状态；无法回读与 Runtime Unknown 分开 |

attempts 等于 accepted、acceptedReplays、rejected、acceptanceUnknown 与 awaitingAcceptance 之和。任务列表和旧键核对不能把连接之前的任务加入分母。原键核对找到任务可以确认一个未知意图，但不证明其所有重试都到达服务器。身份矛盾或观测故障会关闭完整性声明。

latency 用浏览器单调时钟，测量该意图第一次提交到第一次观察到明确终态之间的时间。它包含重试和等待回读的间隔，不是服务器执行耗时。未完成、Runtime Unknown 或时钟异常的耗时为空；P50/P95 只覆盖 knownCount，不能代表缺失样本。终态可能很久没有被回读，应结合 states 与 unknownCount 解释。用量、成本、实际有用性和人工耗时保持 null，不从任务成功推算。

## 留存和合并边界

- 文件只包含固定字段、随机客户端别名、任务顺序别名、时间、状态和数值；不会导出令牌、地址、身份摘要、任务 ID、幂等键、正文或回包。
- 同一 scopeId 的多份文件是累计快照，不能相加。保留原始文件，按 capturedAt 选择当前快照并检查计数是否连续。
- 不同 scopeId 之间不能证明任务互不重叠；不能直接合并成全局唯一任务或全局成功率。scopeId 为空表示观测生成失败，该集合不具备完整性证据。
- 刷新前未导出的区间、服务器重启或台账淘汰造成的缺口不得补算为零；线上采用之前的历史区间不能回填。
- 真实评价、返工和维护记录仍需实际发生后单独登记。合成测试文件只证明导出功能，不作为真实使用样本。
