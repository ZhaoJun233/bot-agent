# 查询先前操作的安全记录

保存后没有收到结果时，保留原操作标识和所属插件 ID。概览页的“核对先前的操作”可以在业务未就绪时读取已留存的安全记录；进入管理员模式后提交查询。该入口只查询，不执行原操作。

## 结果含义

| 结果 | 后续处理 |
| --- | --- |
| 已提交 | 原记录确认事务已提交；业务详情需在对应插件恢复后查询。 |
| 已拒绝 | 原记录为拒绝状态；核对拒绝原因后另行处理。 |
| 结果未知（Unknown） | 保留原标识并核对实际状态，避免重复提交。 |
| 未找到 | 不能据此证明操作没有执行，先确认插件 ID、原标识和调用者身份。 |
| 记录损坏 | 保留原标识和原文件，修复证据后再核对；不回退成“未找到”。 |

查询受现有管理员鉴权及调用范围约束，其他调用范围不能读取这条证据。切换令牌、模式、插件 ID 或原标识会使未完成的查询失效，迟到的响应不能覆盖当前表单。

## 接口与持久化

`POST /zba/v1/operations/find` 接收 `owner` 和 `idempotencyKey`；示例插件 ID 为 `preset.feature.token-quota`。原标识按原样传递，不去掉首尾空格。宿主通过 `operations.find` feature 宣告支持；支持时前端管理员权限探测也走这个只读查询，不依赖业务任务接口。

响应包含 `found`、`receipt` 和 `details`。当前 `details` 为 `unavailable`，未找到时 `receipt` 明确为 null。安全记录仅有格式版本、owner、调用范围/原键/请求摘要、契约及版本、实现代次、状态和来源，不含业务结果、来源名称、消息、原标识或调用者原文。

新配额保存把业务回执、安全索引和审计放在同一个事务。原键重放返回旧结果，不重新写入或重标实现代次；Unknown 证据也不能被此接口改成已提交。安全索引存在但损坏时返回 `operation_receipt_corrupt`，不会改用旧回执掩盖损坏。

旧配额 journal 的兼容读取只检查外层 Fingerprint 和 Result 对象存在性，不解释 Result 内部业务字段、不初始化账本、不修改原字节。旧格式从未记录实现代次，返回 `provenance=legacy`、`generation=null`；不能据此断言旧版实现身份。索引与旧 journal 在同一 SQLite 快照中读取。

当前内置配额以 Storage 模块 MVID 标识实现。托管包可通过宿主批准的资源声明绑定清单摘要与实际激活代次，机制见 [包资源授权](../architecture/plugin-resource-authorization.md)；P08 尚未采用为独立包。本入口不证明整组恢复、物理缺少所有业务包、生产部署或旧宿主整体兼容。

## 验证范围

存储探针覆盖同事务失败回滚、原键/调用范围隔离、Unknown 不重标及损坏格式拒绝。集成 S51 覆盖真实配额提交，S154 覆盖业务未启动时的认证、旧记录与安全索引。浏览器恢复夹具使用缺失的合成模型凭据阻止业务构造，同时保留一份损坏插件元数据；单独损坏元数据会被运行时隔离，不保证整个业务停止。

`BOTAGENT_WEB_TEST_RECOVERY=1` 下运行 `tests/e2e/operation-recovery.spec.ts`，在 Chromium、Firefox、WebKit 的 1280/375 宽度验证实际宿主与页面；查询前后均要求业务 ready=false，且全部 POST 只能到安全查询接口。全部数据、凭据和结果均为合成值。
