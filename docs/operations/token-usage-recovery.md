# schema 15 用量迁移的离线恢复

此命令把**当前** `token_usage` 的计数迁回 schema 14 的配额行，并移除新表。它适用于用量迁移这一恢复单元；不是插件组合回退，也不证明旧宿主能读取当前插件状态。普通启动仍只向前迁移。

## 恢复单元

| 资源 | 恢复行为 |
| --- | --- |
| `token_usage` | 读取当前 prompt/completion、UTC 日期；迁回后删除，始终只有一个计数来源 |
| `tenant_quotas` | 保留当前限额和已有行；恢复旧计数/日期/派生节能列；只有用量的新租户使用 schema 14 的默认限额 50000 |
| 配额 revision、原键回执和审计 | 原样保留；不回放写请求，不重新生成历史回执 |
| 其他包的表、文件和新数据 | 不恢复旧快照、不修改 |

逆迁移的列变更、当前计数复制、新表移除及 `user_version=14` 在同一 SQLite 事务提交；任一步失败全部回滚。缺失配额表、未知 schema、异常数据形状，以及涉及这两个表的额外视图、触发器、外键等依赖均拒绝恢复，需要先确定对应的组合恢复范围。

## 迁移代码归属

配额表的创建、旧计数转出和逆向恢复位于 packages/token-quota/backend/Schema/，并作为固定资源进入配额包。通用计量表的建删位于 src/BotAgent.Storage/Schema/。宿主只负责这次历史迁移的顺序、事务和版本标记。

Storage 同时保留同源的两份配额历史脚本，离线命令直接读取程序集内的固定资源；物理缺失业务 DLL 或发行 ZIP 时也无需启动业务包。构建显式列出资源身份，架构探针在实际源 owner 计数，测试核对包与宿主保留字节一致。这个固定历史恢复入口不接收外部 SQL、包目录或清单中的新迁移；未来包版本的 schema 准入、代次与组合恢复仍须经对应协议实现和验证。

## 操作顺序

1. 记录旧候选及当前候选摘要，先检查旧候选的完整插件状态兼容性：`dotnet <当前宿主.dll> --check-plugin-state <插件根> --candidate <旧宿主.dll>`。状态不兼容时停止；不要删除字段或丢弃 Pending/Previous 来骗过检查。
2. 按发布流程取得维护授权，停用入口并排空任务，让所有数据库使用进程优雅退出；副作用结果为 Unknown 的操作先按原键核对，不自动重放或重启旧组合。停止协议接收与模型任务的范围须与维护方案一致。
3. 保留当前现场及一致性备份，登记 schema、用量行数/汇总、UTC 日期分布、限额与回执摘要、其他包对账项。只记录形状和摘要，不输出会话或成员内容。保留 WAL/SHM 的一致性，不复制正在写的裸数据库。
4. 使用**包含此命令的当前宿主**执行，显式指定现有数据库：

   ```powershell
   dotnet ./release/BotAgent.Headless.dll --recover-token-usage ./data/botagent.db --to-schema 14
   ```

5. 成功输出 `{"status":"recovered","fromSchema":15,"toSchema":14}`。在仍然停写时核对 schema、唯一计数来源、迁移前后计数/日期/限额，以及原回执和其他包对账项；再按已批准的组合切换旧候选。
6. 启动后核对管理/业务就绪与相关入口，观察计数继续累积；保留现场及回滚记录。重新运行新版宿主会正向迁回 15，并保留旧版期间的新增计数。

## 拒绝与中断

| 退出码 | 含义与动作 |
| --- | --- |
| 0 | 事务已提交；先对账，再启动目标候选 |
| 2 | 参数不正确；不会启动业务 |
| 3，`database_in_use` | 无法取得独占占用锁；核对仍存活的宿主/存储进程，不删除锁文件强行继续 |
| 4，`token_usage_recovery_refused` | schema、关联资源、数据约束或文件访问不满足要求；保留原库并检查受影响资源 |

未收到终态响应不能判定事务未提交。保持停写，先核对实际 schema 和数据：15 表示仍处于新版形状，14 表示应对账已恢复状态；其他形状停止处理。命令不会对 schema 14 重复恢复，重复运行返回拒绝，不能把拒绝当成第一次没有提交。

正常初始化持有共享进程锁；离线恢复要求独占锁。目录链接和文件符号链接按物理路径协调。锁文件应随数据库保留，不在进程存活期间删除或替换；它不代替停止未使用本存储模块的外部 SQLite 工具，也不排空模型/协议副作用。禁止通过硬链接或其他数据库别名绕过同一数据库的维护边界。

## 验证边界

合成测试覆盖实际进程占用与目录链接、恢复中途约束失败、额外资源依赖、未来版本拒绝、最新计数和其他包数据保留、原回执及再次升级。历史 schema-14 的 Core/Storage 原源码在独立目录构建，验证了恢复前拒绝、恢复后读取/回执重放/继续计数。历史读取器验证只证明该存储恢复单元；整组插件状态、Linux/Docker、生产维护及真实目标行为仍各自验收。
