# examples/scenarios —— 三套**无密钥**合成场景配置

这三份 JSON 是V3 §11.1 要求的三套场景配置，**不包含任何密钥、真实群号、真实域名或 IP**，
可以直接对照着在面板里手填，或 `POST /api/settings`（面板值压过 env；改完必须保存才生效）。

| 文件 | 场景 | 想演示什么 |
| --- | --- | --- |
| `on-demand.json` | 按需参与 | 只在明确被 @ / 被回复时说话（**打开参与闸门**：普通消息不叫模型）；工具面收到最小（联网/音乐/语音/表情包/戳一戳全关） |
| `research.json` | 资料讨论 | 允许**受限**的搜索与网页读取（预设：单轮预算 2 次）；仍然没有额外动作 |
| `social.json` | 多人交流 | 允许有限度参与与额外动作；**打开人工审批**（默认只覆盖固定假工具 `demo.echo`） |

## 怎么用

```powershell
# 例：把 social 那套打到本机面板（面板必须开着；这是等价于“点保存”的那一个请求）
curl -X POST http://127.0.0.1:8080/api/settings -H "Content-Type: application/json" `
     --data-binary "@examples/scenarios/social.json"
```

- `_comment` / `_howToApply` 两个下划线开头的键只是说明，请求会被服务端忽略（服务端只认它认识的名字）。
- **恢复原样**：把 `scenarioPreset` 与 `enableApprovals` 清空/关掉再保存一次即可 —— 留空 = 与改造前逐字一致。

## 这三套配置**不会**做什么（演示时的诚实边界）

- 不会连真实 QQ、不会连真实模型、不会用真实密钥 —— 演示一律跑**假模型 + 假协议端**（见 `docs/engineering/demo-script.md`）。
- 场景预设**只能收紧**：它不会把面板里已经关掉的能力打开；名字写错 → 按**最低权限**处理（一个能力都不开）。
- `social` 里打开的审批**只覆盖固定假工具** `demo.echo`（一行日志 + 一句回执），**不代表**系统具备 shell / 文件 / 进程控制能力。
