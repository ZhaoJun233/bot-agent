# Reply pacing state probe

This executable tests the synchronous coordinator using synthetic keys, opaque source tickets, a tick-exact fake clock, and injected integer draws. It links only the coordinator source, not the Engine or Host projects, so its build does not touch another project's output directories.

Run from the isolated worktree root:


```sh
dotnet build tests/BotAgent.ReplyPacingProbe/BotAgent.ReplyPacingProbe.csproj -c Release -t:Rebuild --artifacts-path .tmp/pacing-boundaries-artifacts
dotnet .tmp/pacing-boundaries-artifacts/bin/BotAgent.ReplyPacingProbe/release/BotAgent.ReplyPacingProbe.dll
```

## Integration contract

- Call `Observe` on ordinary conversational ingress after immediate commands have been handled. Use the appended human message's conversation-local `ChatMessage.Seq` (not a separate counter) and preserve the opaque source ticket; the coordinator never inspects message content. Duplicate sequences from one speaker cannot create another opportunity; out-of-order distinct speakers remain independent.
- `Created` schedules a new pump; `Updated` pulses the existing owner. Refused/completed turns remain tombstones while that same speaker is still inside its quiet window. Explicit ingress can create a fresh accepted request after refusal.
- Same-sequence explicit confirmation promotes only the latest active or probability/cooldown-refused unsent human request. It preserves the policy/quiet snapshot and does not draw again; older, completed, effects-committed or first-sent requests cannot revive. The latest refusal remains addressable for asynchronous quote confirmation even after quiet.
- Call `ObserveContinuation(key, speakerId, sequence, messageId, ticket)` on gate-rejected appended human ingress only to merge into an existing authorized active request or unsent terminal same-human quiet window, including preempted, not-sent and ineligible soft drafts. It cannot create an opportunity or inherit another human's permission. Effects receive quiet-only updates without changing their accepted snapshot or consuming later followup admission; repeated sequence notifications do not reset quiet.
- Call `ObserveAcceptedResult(key, contextSequence, isGroup, options, ticket)` for an already accepted background-task result. It is independently owned explicit/immediate/non-soft work, does not read or advance human/proactive admission watermarks, and never absorbs human continuation. The caller owns result identity/deduplication; repeated calls intentionally create separate results. Existing capacity, generation serialization, disable handoff and stop still apply; a fully sent group result extends group cooldown.
- `ObserveProactive` uses the same conversation human-sequence identity. A timer cannot reroll an opportunity already observed by any ingress.
- Wait using `GetReadiness` outside the serialized conversation queue. `TryBegin` reserves one generation slot per conversation and performs at most one probability draw per turn. Quiet explicit candidates outrank ordinary work. Full ordinary queues yield expendable capacity to an explicit request; already accepted explicit/effects/sending work is never evicted.
- A generation captures version, trigger ID, human sequence, explicit type, options and ticket. Never rebuild its options from current settings.
- `EndAttempt` releases the generation slot after a call finishes or yields, without invalidating a retained draft. Do not call it while a model/tool call is still running. All quiet waits occur after releasing the queue. A 50 ms `Busy` delay is a scheduling hint, not an internal timer.
- `CheckFreshness` and both commit gates return `Ready / Wait / Retry / Terminal`. On `Wait` with `DiscardDraft=false` keep the same immutable generation and recheck later. On `Retry` discard the generation and call `TryBegin` once immediately. On `Wait` with `DiscardDraft=true` discard it, wait for a genuine quiet window, then call `TryBegin`. Old invalidated generations always fail closed.
- A 12-second soft draft is permanently tool-free, including its immediate retry when the speaker is still typing. It cannot be sent before quiet. Repeated stale inputs permit just one immediate recomputation, then require genuine quiet; the first-arrival clock is never reset.
- Reserve `TryCommitEffects` immediately before the first irreversible task action; never invoke that action twice for the same generation. Later same-human input updates the accepted result's quiet clock but creates/updates a separately owned follow-up. It cannot trigger regeneration of the accepted task. Input from others does not extend that clock.
- Reserve `TryCommitFirstSend` immediately before the first actual segment. Afterwards no automatic replay/retraction is permitted. Send-time source authorization and stop/cancellation remain the caller's responsibility.
- Call `Complete(turn, fullChatSend)` exactly at final outcome. Pass true only for nonempty output after every segment succeeds. False covers empty replies, cancellations, failures and partial sends. Group cooldown starts at this completion time, includes explicit responses, and is independent per conversation. Completion is idempotent. Private responses never establish group cooldown.
- `Disable` drops unsent ordinary work and returns each unsent explicit ownership snapshot to legacy once; old pacing handles immediately become terminal. Legacy calls `Complete` on that same handle after its outcome. Already committed effects/sending retain their immutable options and current owner. `Enable` does not revive tombstones.
- `Stop / Dispose` fence all active handles permanently. The caller must cancel its own async work: the pure state machine contains no timers, tasks, IO or cancellation callbacks.
- All state is protected by one documented lock. Clock/random delegates must be fast, nonblocking and non-reentrant. Diagnostics contain fixed enum reason counters only; snapshot/handle/generation string representations never include source data.

## Evidence and limits

- Latest local run: **34/34 scenario groups passed**, forced Release rebuild with warnings treated as errors and the generated DLL executed explicitly. The coordinator requires an injected clock; runtime and synthetic callers already provide one.
- Covered: A01-A09 and A11-A15 state portions, including all 100 deterministic percentile draws at two probabilities, 64 concurrent distinct speakers, exactly-once handoff/commit, all-segment cooldown, private isolation, soft-draft retry exhaustion and overload behavior.
- Initial compilation succeeded. First probe run was 18/20: one test wrongly treated input after a fully elapsed quiet window as the previous refused opportunity; another used floating-point `DateTime.AddSeconds` values that differed by one tick at a boundary. The former now creates a refused soft opportunity still within quiet; the fake clock now rounds ticks. Corrected 20/20, then expanded 23/23 passed.
- The very first shell invocation ran from the harness workspace rather than the changed file-tool directory and reported a missing project; it built nothing. All subsequent commands explicitly selected the isolated worktree.
- The accepted-result/ingress extension initially failed compilation because four new assertions referred to a nonexistent fixture helper. Corrected to the existing `TryBegin` API; the isolated probe then passed 31/31. Added coverage for result/watermark isolation, cooldown extension, capacity and ownership, latest-only explicit promotion, continuation-only admission fencing, refusal quiet windows and retained-effect followup admission.
- Soft-terminal regression: continuous ordinary input at seconds 0, 2, ..., 12 draws once; after Preempted/NotSent/Ineligible, context-only input at 14 must keep eligible input at 16 on that terminal opportunity. All three initially failed with `Expected Terminal; got Created.` (31/34). The narrow continuation predicate fix passed 34/34, including duplicate-input quiet stability, a fresh opportunity at the exact actual quiet boundary, and no late-explicit revival of these terminal reasons. A missing-clock assertion separately failed 33/34 before mandatory clock injection restored 34/34.
- These are pure-state results, not evidence for transport acknowledgements, model/tool side effects, queue wait placement, source lease revocation, real API/UI settings, or no-double-send in the integrated pipeline. Lead-owned integration probes must verify those boundaries separately. No production inputs or services were used.
