联网搜索

            
模型可以要求去网上查一下（JSON 里填 search 字段）或读一下某个网页（read 字段），
              查到的东西会作为事实交给它，下一轮再拿着事实回答 —— 而不是靠印象编。
              默认走模型自带搜索（检索在模型服务商那边完成，结果自带来源）；它不可用时才回退到下面的搜索源。

                「设备名」到底是什么？怎么把一台机器接上来（点开看）
                

                    设备名就是本机桥握手时报上来的名字：默认取本机主机名（Windows 的 COMPUTERNAME，比如 ZHAOSPC），
                    也可以用 --name / PI_BRIDGE_NAME 自己指定。

                    这里是“按名字认设备”的：面板里填的名字要和本机跑的那个名字一致 —— 不一致时它会在表里多出一行（名字为实际报上来的那个），把旧那行删掉即可。

                    
把一台机器接上来（三步）：

                    
    
                        
  1. 本机装好 pi（本机 agent 的干活工具），并确认 pi --version 能跑；Python 3 也要有。
    2. 
                        
  2. 点上面「一键连接本机…」→ 填一个名字（比如 ZHAOSPC）→ 下载两个文件（connect-pi-bridge.cmd 与 pi-bridge.py）放到同一个目录。
    3. 
                        
  3. 双击 connect-pi-bridge.cmd（Windows）或 sh connect-pi-bridge.sh（Linux/Mac）——窗口别关。
                            回到这里点「我已运行，检测连接」，看到 🟢 在线就成了。
    4. 
                    


                    
不想用一键脚本（手动）：
                        在本机跑 python pi-bridge.py --name 你的设备名 --url ws://机器人地址/agent-bridge --token <AGENT_TOKEN> --workdir 你的目录。
                        令牌在容器环境变量 QQCHAT_AGENT_TOKEN 里（也可用面板“一键连接”生成的脚本里看到）。


                    
连着的时候能做什么 / 断了怎么办：
                        在线时下面会列出它的模型（可选一个默认用它）；点「断开」会真的断开，但本机那个窗口还开着的话，它 3 秒后会自己重连；
                        要让某台设备彻底不干活，就把它的「启用」关掉（关掉后群里的 // 会如实说“设备在面板里被关掉了”）。

服务器健康日报

            
每天在指定时刻（北京时间）发一条机器人 / 服务器状态：QQ 在线与协议端连接、
              模型接口通不通、内存/负载/磁盘、日志大小与近一小时告警。
              整条链路只用机器人自己（自己的定时器 → 自己采集 → 按收件人所在通道发出去），不经过本机 agent ——
              你那台电脑关着也照样收得到。

        
收件人可以是私域真号，也可以是官方通道的别名号（两条通道都适配了）；
          走官方那边属于平台的「主动消息」，算平台额度（上限很宽松，但别拿去刷屏）。
          哪个通道的「对话总开关」关着，就不往哪条通道发 —— 日报不会绕过总开关。

          


          

          

            

              
              
            

            

              
              
            

          


          

            
            
            
          

          


          
为什么不用「本机 Agent」来推：那台电脑可能根本没开机。日报只依赖机器人容器与协议端，
            所以它就是“机器人报平安”的那条链路。到点时如果协议端不在线，这一天的那条会发不出去（日志里有记录，
            面板上也能看到「上次失败」）。

能力与审批增强能力：默认关闭，不改现有行为

            
场景预设留空 = 能力白名单完全由上面的开关决定（与以前一样）；填了预设只会收紧，
              不会把已经关掉的能力打开，名字不认识则按最低权限处理。

              人工审批打开后，模型说“想调工具”不会被执行，而是发一张待确认到群里：
              群主/管理员（或下面点名的人）回复「同意 编号」才执行 —— 而且只执行一个固定假工具
              （它没有任何真实副作用，不代表具备 shell / 文件 / 进程控制能力）。

          


          

            
            
          

          


          

          

            
            
          

          


          
          


          

            
参与状态机只观测，不改“发不发”的判定

            
机器人按会话记一份参与状态（观望 / 试探 / 活跃 / 退场），下面这组是**服务端硬上限**：
              填大了会被钳到上限（连续 ≤10、冷却 ≤600 秒、试探 ≤3、活性命 ≤3600 秒）。

              现在它只写观测日志（日志里搜 [参与]），改这些数字不会改变群聊行为 ——
              这是刻意的：等真实使用观测对得上，再谈用它来拦。
